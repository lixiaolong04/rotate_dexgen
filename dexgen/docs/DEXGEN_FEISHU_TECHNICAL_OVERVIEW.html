01项目目标：完成了什么

从单一自主策略，扩展为可交互、可生成、可部署的灵巧操作系统。

本项目面向 XHand1 Pro 的圆柱物体手内旋转任务。上游工作已经通过强化学习获得可稳定执行顺时针（CW）和逆时针（CCW）旋转的专家策略；本阶段在此基础上跑通 DexGen pipeline，将专家行为转化为可学习的轨迹数据，再训练生成式动作模型与学习式逆动力学模型，并接入 MANUS 手套和真机控制栈。

数据双向专家轨迹

冻结 CW/CCW RL 专家，采集关节、PD target、关键点、触觉、物体状态、奖励和终止信息。

生成关键点运动规划

条件 Diffusion 根据当前状态、历史、方向和可选 guidance，生成未来两帧十个关键点的运动。

控制关节目标映射

IDM 将关键点运动转换为 21 维绝对 PD target，使生成结果能够驱动 XHand。

交互MANUS 三态控制

利用手套输入实现 CW、CCW 和 HOLD；HOLD 锁存机器人当前姿态，不会张手掉物。

项目边界：DexGen 不是新的 RL 策略。RL 专家是行为数据的来源；DexGen 学习专家运动分布，并提供关键点空间生成、外部 guidance 和人机交互能力。

02为什么手内旋转难，而且值得做

它同时考验接触控制、部分可观测性、长时稳定性和 Sim-to-Real。

多点接触持续切换

五指需要交替松开、重抓和施力。接触点、摩擦状态和受力平衡持续变化，很难用固定轨迹或解析模型精确描述。

物体状态不可直接观测

物体被手掌遮挡，部署状态主要依赖关节本体感知与五指触觉。策略需要从短时历史中推断滑移和接触变化。

旋转与抓稳相互制约

握得过紧，物体无法转动；握得过松，物体会掉落。持续旋转需要不断在推进和稳定之间动态权衡。

误差会在长时运行中积累

单步误差很小，也可能在几十秒后演变为错向旋转、接触丢失或物体掉落，因此必须用闭环指标而非只看训练 loss。

仿真与现实的接触鸿沟

摩擦、软指尖、执行延迟、传感器偏置和电机响应难以完全建模，是灵巧手 Sim-to-Real 中最敏感的一类任务。

交互命令不能破坏稳定性

方向切换与停止不能直接粗暴覆盖关节动作，尤其 HOLD 必须保持夹持，而不是照搬操作者张手姿态。

04上游专家：强化学习策略从哪里来

先用强化学习解决“如何转”，再用 DexGen 学习和重组专家行为。

4.1 任务形式化：观测、动作与目标

上游旋转策略运行在 NVIDIA Isaac Sim / IsaacLab 中。机器人为 21 自由度 XHand，策略输出每个关节的动作目标，底层由显式 PD 控制执行。训练目标是在保持物体不掉落的同时，沿指定方向持续产生有向角速度，并抑制物体平移、无效能耗和剧烈动作。

策略可获得的信息

  • 关节角、历史动作目标等本体状态
  • 五指触觉标量及其时间变化
  • Teacher 训练阶段可使用物体和物理参数等特权信息

策略需要输出的行为

  • 21 维关节动作 / 目标
  • 连续换指和接触重建
  • 朝 CW 或 CCW 的稳定有向旋转
  • 遇到滑移和扰动时重新抓稳

4.2 Teacher：特权信息强化学习（PPO）

Teacher 在大规模并行仿真中通过 PPO 试错学习。训练时可访问真机上难以直接获得的物体状态与物理参数，因此能够更快形成有效的旋转行为。Actor 决定动作，Critic 评估长期回报，PPO 的裁剪目标限制策略单次更新幅度，提升高维接触任务中的训练稳定性。

LCLIP(θ) = E[min(rt(θ)Ât, clip(rt(θ),1−ε,1+ε)Ât)]策略更新既追求更高回报，又避免一次更新偏离旧策略过远。

4.3 域随机化：鲁棒性的来源

训练时随机化物体尺度、质量、质心、摩擦、重力方向、执行器和传感器相关参数，让策略在每个 episode 面对略有不同的“世界”。这相当于训练一组对物理误差不敏感的行为，而不是记住单一仿真参数。

核心思想：现实参数不可能被完全测准，与其追求一个完美仿真，不如让策略在足够宽的参数分布上学会自适应。

4.4 Student：隐状态回归蒸馏

Teacher 能看到特权信息，但真机部署看不到。ProprioAdapt Student 只使用真实系统可获得的本体状态与触觉历史，通过时序网络推断隐含的物体与动力学状态，并模仿 Teacher 动作。最终用于 DexGen 轨迹采集的是已训练好的 Student 专家。

方向专家权重用途
CW（顺时针）student_9402.pth采集 CW 稳定旋转与恢复轨迹
CCW（逆时针）student_9503.pth采集 CCW 稳定旋转与恢复轨迹
方向契约不可破坏：CW/CCW 标签和专家权重不能互换。采集器会检查有向转速符号；方向错误的数据会直接污染后续条件生成模型。

05从专家到数据：轨迹如何构造

专家 rollout 不只是录动作，而是保存可用于生成、逆动力学与恢复学习的完整时序。

5.1 为什么选择十个手部关键点

直接在 21 维关节空间学习，会把 XHand 特定的关节结构绑定到生成模型。项目使用腕坐标系下的十个关键点——五个 PIP 点和五个指尖胶垫点——作为中间动作表征，既保留抓取几何，又更接近“手指要移动到哪里”的任务语义。

06DexGen 核心算法：Diffusion + IDM

一个模型负责“想动作”，另一个模型负责“把动作变成关节控制”。

6.2 Guided Diffusion：生成未来关键点运动

Diffusion 不直接一次性回归唯一动作，而是学习专家关键点运动的条件分布。训练时逐步给真实运动加入高斯噪声，网络学习在给定状态和方向条件下预测噪声；推理时从噪声出发迭代去噪，得到符合专家分布的未来运动序列。

xt = √ᾱtx0 + √(1−ᾱt)ε，   L = E[‖ε − εθ(xt, t, c)‖²]x₀ 为真实关键点 motion，c 包含状态历史、CW/CCW 方向、触觉以及可选外部 guidance。

正式配置使用 100 个 diffusion steps、cosine noise schedule 和 epsilon prediction；在线通过 DDIM 缩短采样，默认可使用 25 步，在速度和生成质量之间折中。

为什么使用 Diffusion：同一个接触状态往往存在多种有效换指动作。生成模型可以表达“多种都合理”的动作分布，并允许在采样时加入方向或 MANUS 关键点 guidance，而不是被单一均值动作限制。

6.3 Guidance：在专家分布内引导动作

MANUS 或 noisy-RL 可以给出十个关键点希望移动的方向。采样过程中将该目标转成 guidance cost 的梯度，引导生成结果接近命令，同时保留模型从专家数据中学到的稳定抓取先验。

x* = arg minx [ Ediffusion(x | state, mode) + λ · ‖x − xcommand‖² ]λ 控制服从外部命令与保持专家运动先验之间的权衡。

6.4 IDM：从关键点运动到 21 维关节目标

IDM（Inverse Dynamics Model）接收机器人当前状态与未来关键点运动，预测下一规划时刻的 21 维绝对 PD target。它学习了“为了实现这段指尖/PIP 运动，XHand 各关节应到达什么目标”的映射。

术语说明：项目交流中有时把 IDM 称为“逆运动学模型”，但它不是只根据几何求解关节角的传统解析 IK。它是从专家数据监督学习的逆动力学/动作映射模型，条件中还包含当前状态与时序信息。

6.5 为什么先训练 IDM，再训练 Diffusion

  1. 先把数据中的真实未来关键点 motion 输入 IDM，检查 21 维 target 是否能够准确重建。
  2. 若 oracle motion → IDM 误差较小，说明关键点表征和关节映射成立。
  3. 再训练 Diffusion，并检查 Diffusion motion → IDM 的串联误差。
  4. 最后进入 Isaac 闭环，区分生成误差、IDM 误差和真实执行跟踪误差。

07鲁棒性：触觉条件与主动恢复

蒸馏不是终点；长期运行要求模型见过“快要失败时应该怎么救”。

稳定专家轨迹主要集中在正常旋转区域，但真机中不可避免会出现动作偏差、手指短时失去接触或物体受外力。如果训练集只有稳定状态，模型在分布外状态下无法知道如何回到安全区域。因此项目专门构造主动恢复数据：

01
稳定旋转
RL 专家在正常分布中持续 CW/CCW
02
注入扰动
action bias / 单指释放 / 物体外力，持续约 0.2 s
03
恢复控制权
停止扰动，由干净 RL 专家接管
04
标记成功窗口
未掉落、≥3 指接触、沿目标方向继续旋转
05
重采样训练
显式提高成功恢复窗口占比

五指触觉按照 thumb / index / middle / ring / pinky 的固定顺序输入。active-recovery v3 使用 v2b 触觉架构，通过独立时序编码器提取五指接触变化，并用未来触觉辅助目标帮助模型学习滑移与恢复趋势。

恢复成功不是“物体暂时没掉”：还要求至少三指保持接触，并且物体重新产生不低于阈值的目标方向转速，从而避免模型只学会夹死物体。

08MANUS 人机交互：正转、反转与停止

手套提供的是高层意图；机器人仍由稳定动作模型负责执行。

8.1 MANUS guidance 链路

MANUS 数据经过 RetargetX 得到 21 维手套关节目标，并通过 TCP 8020 发送。标定后，用手套关键点相对参考姿态的变化构造十点 motion command：

xgoal = xrobot,ref + gain · [FK(qglove,now) − FK(qglove,ref)]
command = xgoal − FK(qrobot,now)手套只提供相对关键点 guidance，不直接加入 Diffusion/IDM 的状态向量。

8.2 三种运行路径必须区分

控制路径数据流用途

8.3 自动 CW / CCW / HOLD 状态机

系统利用个人标定的 CW、CCW 手势原型判断方向趋势。完全张掌持续约 1 秒进入 HOLD；恢复自然抓握约 0.2 秒后，回到进入 HOLD 前的旋转方向。

图 4：MANUS 三态控制逻辑。HOLD 绕过 Diffusion/IDM，避免张掌手势导致机器人松手。

安全原则：TCP 数据过期、断连、reset 或关节契约失败时必须 disarm 并保持安全 PD target，绝不能把“没有新数据”解释为“操作者要求静止”。

09从仿真到真机：四个关键对齐

Sim-to-Real 的重点不是单一模型，而是状态、动作、时间和安全契约的一致。

01状态与触觉对齐

部署使用 83 维状态：78 维本体状态 + 五指触觉。传感器 profile、指序、归一化统计必须与训练 checkpoint 一致。

02动作与关节对齐

IDM 输出绝对 PD target；真机端严格执行关节名称重排、物理限位和单周期变化限幅，避免索引错位造成猛动。

03控制时序对齐

生成规划 10 Hz、底层任务 20 Hz。MANUS 约 80 Hz 输入使用 latest-frame 语义，避免积压旧帧引入额外延迟。

04硬件安全对齐

固定 mode=4、kp=10、kd=0.3、speed=0、torque=0；温度或厂商错误触发 mode 0，退出使用安全松手轨迹。

9.1 分阶段验收顺序

数据审计确认 episode 数量、方向符号、触觉分布、扰动类型和有效训练窗口。
IDM Oracle 验收用真实 future motion 检查关节 target MAE，隔离运动映射能力。
Diffusion 离线串联检查 motion MAE/RMSE、幅值比、相关性和 Diffusion → IDM target MAE。
Isaac 短时闭环先 smoke test，再进行 CW/CCW、多 seed、固定 exposure 的正式评估。
MANUS 输入与仿真完成 30 秒数据探针、个人 profile 标定、方向和 HOLD 测试。
XHand 真机分阶段测试连接 → 预抓取 → 3–5 秒旋转 → HOLD → 恢复 → 安全松手。

10.3 工程沉淀

可续跑数据流水线

支持 CW/CCW 分片采集、进度记录、断点续跑和逐分片恢复数据审计。

Checkpoint 合约

约束 state dim、history、关键点语义、触觉架构和 normalizer，避免不兼容模型混用。

分层评估体系

覆盖 oracle IDM、离线串联、Isaac 闭环、主动扰动、MANUS 仿真和真机分阶段验证。

真机安全状态机

10.4 当前局限

  • 主动恢复成功率仍约为 73.68%，episode 掉落率约 55%，长时稳定性仍有提升空间。
  • 当前任务和数据以圆柱旋转为主，跨形状、跨尺寸和复杂物体的泛化尚需系统验证。
  • MANUS 方向识别依赖个人 profile 标定，不同操作者之间的通用性有限。
  • Diffusion 迭代采样带来推理开销，需要继续研究更少 DDIM steps、蒸馏或一致性模型。
  • Diffusion 与 IDM 分阶段训练可能产生分布偏差，尚可探索联合训练或闭环数据聚合。
