PPO 训练循环代码

把第 05 章的裁剪目标与第 04 章的 GAE，逐函数对照到 ppo.py 与 experience.py。读完本章，你能画出一次 train_epoch() 里数据怎么流、损失怎么算。

前置阅读。 第 19 章讲 wrapper 如何把 IsaacLab 环境变成 PPO 能用的 reset()/step() 字典；本章假设观测里已有 obs、priv_info。公式推导见 Part A，本章只讲代码落点。

本章术语表

epoch（训练轮）
一次完整的「采样 + 更新」周期。不是指跑完整个数据集一遍，而是 PPO 里的一次 train_epoch()。
horizon_length
每次更新前向环境收集的步数，默认 8。代码里 for n in range(8) 的 n 就是 0…7。
rollout / play_steps
用当前策略在环境里「玩」若干步，把轨迹存进 ExperienceBuffer。也叫 on-policy 采样。
ExperienceBuffer
轨迹记账本，形状 (8, N, dim)。8 是时间步，N 是并行 env 数。
GAE（广义优势估计）
从奖励和价值函数反推「这步动作比平均好多少」（advantage）。实现函数 computer_return()。
mini_epochs
同一批 rollout 数据重复训练几轮（默认 5），每轮切多个 minibatch 做梯度下降。
agent_steps
累计环境步数计数器，每 epoch 加 batch_size = 8 × N，达到 max_agent_steps 停止。
shaped_rewards
进 GAE 的奖励，= 原始 reward × 0.01，超时步再加 bootstrap 项。

零、train() 像「for 学期 in 大学四年」

把 RL 训练想成上大学：
• train() 的外层 while = 整个大学生涯，直到学分修满（max_agent_steps）才毕业。
• 每次循环里的 train_epoch() = 一个学期：先实习采集经验（play_steps），再回校上课改网络（PPO 更新）。
• epoch_num += 1 = 学期编号 +1；write_stats = 期末成绩单写 TensorBoard；save best.pth = 历史最佳作品入档案。
学期与学期之间不断档——上一学期最后一天的环境状态，就是下一学期第一天的起点（不会整校 reset，除非某个 env done 了）。
问：为什么叫 epoch 不叫 iteration？ 历史沿袭 RLGames 命名。在本项目里 epoch ≈ 一次 PPO 更新周期，与深度学习「遍历数据集一遍」的 epoch 含义不同。

horizon_length = 8 是什么意思？

类比：拍一段 8 帧的短视频再复盘。 策略不会每动一下就立刻改参数——那样太噪、太不稳定。PPO 的做法是：先让 N 个并行 env 各连续走 8 步，录下这 8 帧里每一步的观测、动作、奖励、价值估计；8 步走完后，用 GAE 给整段录像「打分」（算 advantage），再用这些分数改网络。

为什么是 8 而不是 80？偏差–方差权衡：看得太短，不知道动作长期后果；看得太长，旧策略采的数据和新策略差太远（on-policy 失效）。8 是 in-hand manipulation 论文与 RLGames 默认值，对本项目够用。改大 → 每次更新前采集更久、显存占用线性增；改小 → 更新更频繁但 GAE 更噪。
数字含义Xhand 默认（N=16384）
horizon_length = 8每 epoch 每个 env 走 8 步—
batch_size = 8 × N一次 rollout 总 transition 数131,072
minibatch_size每次梯度步样本数min(8×N, 32768)
mini_epochs = 5同一批数据训 5 轮梯度步 ≈ 5 × (batch/minibatch)

一、两个文件的分工

PPO 类是"总指挥"：决定何时采样、何时更新、何时存 checkpoint。ExperienceBuffer 是"记账本"：把 8 步 × N 个并行环境的轨迹存成张量，再算 GAE、切成 minibatch 喂给优化器。可以把一次 epoch 想成：先跑 8 步收集经验，再拿这些数据改网络 5 轮（mini_epochs）。

三、train()：外层无限循环

train() 只做三件事循环：① 调一次 train_epoch()（采样+更新）② 写 TensorBoard ③ 按规则存 checkpoint，直到 agent_steps >= max_agent_steps（默认 3e8）。
ppo.py · train() 
def train(self):
    self.obs = self.env.reset()
    self.agent_steps = self.batch_size          # 初始计步偏移

    while self.agent_steps < self.max_agent_steps:
        self.epoch_num += 1
        a_losses, c_losses, b_losses, entropies, kls = self.train_epoch()
        self.storage.data_dict = None           # 释放上一 epoch 的展平缓存

        self.write_stats(...)                   # TensorBoard
        # save_freq / best reward → stage1_nn/*.pth

代码白话

self.agent_steps = self.batch_size计步器初始偏移 = 8×N。这样第一次 epoch 结束后 agent_steps 对齐「已采集过一批」。

注意：self.obs 在 epoch 之间不断档——上一 epoch 的 play_steps 结束时环境已经前进了 8 步，下一 epoch 直接从当前观测继续，不会重新 reset()（除非某个 env 在本 epoch 内 done 后被环境内部 reset）。

四、train_epoch()：采样 + 更新

一个 epoch 分两段，计时分别累加到 data_collect_time 与 rl_train_time：

① set_eval + play_steps()

用当前策略采样 8 步，写入 ExperienceBuffer，算 GAE

② set_train + mini_epochs 循环

遍历 len(storage) 个 minibatch，算 PPO loss，backward，Adam step

③ 每个 mini_epoch 末

算平均 KL → AdaptiveScheduler 调 lr

4.1 play_steps()：horizon=8 的 rollout

循环 for n in range(self.horizon_length)，即 n = 0, 1, …, 7。每一步做：

  1. model_act(self.obs) — 归一化 obs，Actor 采样动作，Critic 估价值
  2. 把 obs、priv_info、action、neglogp、value、μ、σ 写入 buffer 第 n 行
  3. env.step(actions) — 经 wrapper 进 Isaac Sim 物理
  4. 奖励塑形 + 可选 bootstrap，写入 buffer
ppo.py · play_steps() 完整核心 
for n in range(self.horizon_length):          # n = 0 … 7
    res_dict = self.model_act(self.obs)
    self.storage.update_data('obses', n, self.obs['obs'])
    self.storage.update_data('priv_info', n, self.obs['priv_info'])
    for k in ['actions', 'neglogpacs', 'values', 'mus', 'sigmas']:
        self.storage.update_data(k, n, res_dict[k])

    actions = torch.clamp(res_dict['actions'], -1.0, 1.0)
    self.obs, rewards, self.dones, infos = self.env.step(actions)
    rewards = rewards.unsqueeze(1)

    self.storage.update_data('dones', n, self.dones)
    shaped_rewards = 0.01 * rewards.clone()
    if self.value_bootstrap and 'time_outs' in infos:
        shaped_rewards += self.gamma * res_dict['values'] * infos['time_outs'].unsqueeze(1).float()
    self.storage.update_data('rewards', n, shaped_rewards)

    # ... episode 统计、extra_info 日志 ...

res_dict = self.model_act(self.obs)
last_values = res_dict['values']
self.agent_steps += self.batch_size
self.storage.computer_return(last_values, self.gamma, self.tau)
self.storage.prepare_training()

代码白话
res_dict = self.model_act(self.obs)对第 8 步之后的新观测再估一次 V，作为 V₈（horizon 外 bootstrap）。
last_values = res_dict['values']GAE 逆推时 t=7 的 next_values 用这个，而不是 buffer 里不存在的 t=8。

computer_return(last_values, gamma, tau)从 t=7 倒推到 t=0 算 GAE advantage 和 returns。
prepare_training()(8,N,dim) 展平成 (8N,dim)，标准化 advantage，准备 minibatch 索引。
奖励为什么要 ×0.01？ 环境原始奖励量级可达几十（旋转进度 + 正则项累加）。Critic 若直接拟合大数值，梯度不稳定。缩放到 ~0.1 量级后，价值网络更好学；策略梯度方向不变（整体乘常数），但 GAE 的 δ 与 returns 数值更健康。部署时不涉及奖励，无影响。
问：为什么先 model_act 再 env.step，而不是反过来？ 标准 RL 记法：在状态 sₙ 下选动作 aₙ，执行后到达 sₙ₊₁ 得 rₙ。buffer 存的是 (sₙ, aₙ, rₙ, V(sₙ))。若先 step 再 act，存的就变成 sₙ₊₁ 上的决策，GAE 时间对齐会乱。

4.2 Value Bootstrap（超时截断）

手内旋转是无限 horizon 任务（is_finite_horizon=False）。episode 因达到 max_episode_length 被截断时，并非真正"失败"，不应把未来价值当 0。Wrapper 把 truncated 放进 extras['time_outs']：

sharpa_wave_env_wrapper.py · step() 
if not self.unwrapped.cfg.is_finite_horizon:
    extras["time_outs"] = truncated

PPO 在塑形奖励上追加 bootstrap 项：

$$\tilde r_t \;=\; 0.01\, r_t \;+\; \gamma\, V(s_t)\,\mathbb{1}[\text{timeout}_t].$$

4.3 循环结束后：末态价值 + GAE

8 步跑完后，再对当前 self.obs 调一次 model_act 得到 last_values，作为 horizon 末步的 $V(s_{T+1})$：

ppo.py · play_steps() 尾部 
res_dict = self.model_act(self.obs)

4.4 PPO 损失（更新段）

set_train() 后，对 mini_epochs × minibatch 双重循环：

ppo.py · train_epoch() · PPO loss 
ratio = torch.exp(old_action_log_probs - action_log_probs)   # r(θ)
surr1 = advantage * ratio
surr2 = advantage * torch.clamp(ratio, 1.0 - self.e_clip, 1.0 + self.e_clip)
a_loss = torch.max(-surr1, -surr2)

value_pred_clipped = value_preds + (values - value_preds).clamp(-self.e_clip, self.e_clip)
c_loss = torch.max((values - returns) ** 2, (value_pred_clipped - returns) ** 2)

loss = a_loss + 0.5 * c_loss * self.critic_coef - entropy * self.entropy_coef \
       + b_loss * self.bounds_loss_coef
loss.backward()
torch.nn.utils.clip_grad_norm_(self.model.parameters(), self.grad_norm)
self.optimizer.step()
PPO loss 计算 · 逐行
代码白话
ratio = exp(old_neglogp - new_neglogp)新策略相对旧策略的概率比 r(θ)。old_action_log_probs 实际存的是 neglogp。
surr1 / surr2 / maxPPO 裁剪目标：限制 ratio 在 [1-ε, 1+ε]，防止一步更新太猛。
c_loss clippedCritic 也做 value clipping，与 05 章公式一致。
- entropy * coef熵奖励，鼓励探索。coef 默认 0 时此项为 0。

policy_kl → scheduler每个 mini_epoch 末算平均 KL，超 2×阈值则 lr÷1.5。

5.3 computer_return()：GAE 实现

experience.py · computer_return() 
def computer_return(self, last_values, gamma, tau):
    last_gae_lam = 0
    mb_advs = torch.zeros_like(self.storage_dict['rewards'])
    for t in reversed(range(self.transitions_per_env)):    # 7 → 0
        if t == self.transitions_per_env - 1:
            next_values = last_values
        else:
            next_values = self.storage_dict['values'][t + 1]
        next_nonterminal = 1.0 - self.storage_dict['dones'].float()[t]
        next_nonterminal = next_nonterminal.unsqueeze(1)
        delta = self.storage_dict['rewards'][t] \
              + gamma * next_values * next_nonterminal \
              - self.storage_dict['values'][t]
        mb_advs[t] = last_gae_lam = delta + gamma * tau * next_nonterminal * last_gae_lam
        self.storage_dict['returns'][t] = mb_advs[t] + self.storage_dict['values'][t]
computer_return · 逆序循环逐行（t = 7 → 0）
代码白话
for t in reversed(range(8))从最后一帧往前算。GAE 需要知道「后面」的 advantage 才能算「前面」的。
t==7 → next_values = last_values第 8 帧之后没有 buffer 里的 V，用 play_steps 末尾 extra model_act 的 V₈。
else → values[t+1]t<7 时，下一状态价值已在 buffer 里（step 前估的 V）。
next_nonterminal = 1 - donesdone=1 的 env 不 bootstrap 未来（episode 真结束）。
delta = r + γV' - VTD 误差 δₜ。用的是 shaped reward。
mb_advs[t] = δ + γλ(1-d)Â_nextGAE 递推。λ=tau=0.95。
returns[t] = adv + values[t]回报 Rₜ = Âₜ + V(sₜ)，Critic 回归目标。
$$\delta_t = \tilde r_t + \gamma V_{t+1}(1-d_t) - V_t, \qquad \hat A_t = \delta_t + \gamma\lambda(1-d_t)\hat A_{t+1}, \qquad R_t = \hat A_t + V_t.$$

5.4 prepare_training()：展平 + 标准化优势

experience.py 
def transform_op(arr):
    return arr.transpose(0, 1).reshape(s[0] * s[1], *s[2:])

def prepare_training(self):
    for k, v in self.storage_dict.items():
        self.data_dict[k] = transform_op(v)
    advantages = self.data_dict['returns'] - self.data_dict['values']
    self.data_dict['advantages'] = ((advantages - advantages.mean())
                                    / (advantages.std() + 1e-8)).squeeze(1)
prepare_training · 逐行
代码白话
transpose(0,1).reshape(8, N, dim) → (8×N, dim)。把「8 步 × N env」打平成一个大 batch。
advantages = returns - values原始 advantage，尚未标准化。
(adv - mean) / std零均值单位方差，稳定 PPO 梯度。+1e-8 防除零。
len(storage) = batch // minibatch决定 train_epoch 内层 for 循环次数。

六、辅助：model_act() 与归一化

ppo.py · model_act() 
def model_act(self, obs_dict):
    processed_obs = self.running_mean_std(obs_dict['obs'])
    input_dict = {'obs': processed_obs, 'priv_info': obs_dict['priv_info']}
    res_dict = self.model.act(input_dict)          # 采样，含探索
    res_dict['values'] = self.value_mean_std(res_dict['values'], True)  # 反归一化存 buffer
    return res_dict
model_act · 逐行
代码白话
running_mean_std(obs)play_steps 时 model.eval() + RMS.eval()，只归一化不更新统计。
model.act(...)高斯采样探索。返回 actions, neglogpacs, values, mus, sigmas。
value_mean_std(..., unnorm=True)价值反归一化后再存 buffer，GAE 与原始 reward 量级一致。

采样阶段 model.eval()；更新阶段 model.train()，obs 在 minibatch 里再过 running_mean_std 且处于 train 模式以更新均值方差。详见第 08 章。

九、train_epoch() 完整两阶段

ppo.py · train_epoch() 结构 
def train_epoch(self):
    _t = time.time()
    self.set_eval()
    self.play_steps()
    self.data_collect_time += (time.time() - _t)

    _t = time.time()
    self.set_train()
    for _ in range(self.mini_epochs_num):       # 5 轮
        ep_kls = []
        for i in range(len(self.storage)):    # batch/minibatch 次
            # ... PPO loss, backward, step ...
            ep_kls.append(kl)
        av_kls = torch.mean(torch.stack(ep_kls))
        self.last_lr = self.scheduler.update(self.last_lr, av_kls.item())
    self.rl_train_time += (time.time() - _t)
    return a_losses, c_losses, b_losses, entropies, kls
train_epoch · 逐段
代码段白话
set_eval(); play_steps()采样阶段：网络 eval，RMS 不更新，只收集数据。
data_collect_time += ...累计采样耗时，TensorBoard 算 EnvStepFPS。
set_train()更新阶段：网络 train，RMS 在 minibatch 里更新统计。
for mini_epochs同一批 8N 数据重复训 5 遍，提高样本利用率。
for len(storage)每个 minibatch 一次梯度步。N=16384 时约 5×4=20 次 step/epoch。
scheduler.update(lr, kl)每个 mini_epoch 末根据 KL 调 lr，防策略突变。

十、AdaptiveScheduler 与 KL 刹车

ppo.py · AdaptiveScheduler 
def update(self, current_lr, kl_dist):
    lr = current_lr
    if kl_dist > (2.0 * self.kl_threshold):      # 默认 threshold=0.008
        lr = max(current_lr / 1.5, self.min_lr)
    if kl_dist < (0.5 * self.kl_threshold):
        lr = min(current_lr * 1.5, self.max_lr)
    return lr
AdaptiveScheduler.update · 逐行
条件动作
KL > 2×0.008 = 0.016策略变化太猛 → lr ÷ 1.5，最低 1e-6
KL < 0.5×0.008 = 0.004策略几乎没变 → lr × 1.5，最高 1e-2
中间区域lr 保持不变
问：policy_kl 怎么算的？ 用更新后新 μ,σ 与 buffer 里旧 μ,σ 算高斯 KL 解析式（policy_kl() 函数），对动作维求和再 batch 平均。不是采样估计。

十二、FAQ

问：--num_envs 10 时 batch_size 多少？ 8×10=80。每 epoch 只采 80 条 transition，minibatch_size 也被 train.py cap 到 80，更新很快但样本少，适合调试显存。
问：能否 horizon_length=1？ 理论上可以，但 GAE 几乎退化成单步 TD，advantance 方差极大，训练不稳定。不建议低于 4。

十三、epoch 计时字段

PPO 在 __init__ 初始化三个计时器：data_collect_time（play_steps）、rl_train_time（backward 段）、all_time。TensorBoard 的 EnvStepFPS = agent_steps / data_collect_time，反映采样吞吐而非整体吞吐。

问：Last FPS 和 EnvStepFPS 区别？ train() 打印的 Last FPS = 最近一个 epoch 的 batch_size / epoch_wall_time。EnvStepFPS 是累计 agent_steps / 累计 data_collect_time。后者更能看长期采样效率。
21 维独立高斯，log prob 对各维相加得联合 log prob。PPO ratio 用标量 log prob 比，所以 log_prob(...).sum(1) 得 (N,) 而非 (N,21)。
问：storage.update_mu_sigma 干什么？ 每个 mini_epoch 更新后，把新 μ,σ 写回 data_dict 对应 minibatch 区间，供下一 mini_epoch 算 KL 时与「上一轮更新后的策略」对比。实现上是在线策略迭代的近似。
