抓取缓存与 gen_grasp

训练旋转任务前，必须先有一批「已经稳稳抓住圆柱体」的起手姿态。本章讲 gen_grasp.py 如何用专用 Grasp 环境自动收集这些姿态，存成 .npy（像 Excel 一张表），以及训练环境 _reset_idx 如何从中采样——含 cond1/cond2/cond3 具体数字举例。

为什么需要抓取缓存？ 旋转 RL 的 episode 从「手已经握住物体」开始。若每次 reset 都从张开的手 + 空中落下的物体起步，策略要花大量步数学「先抓住」——而这不是旋转任务的目标。预先生成几千个经过物理验证的抓取姿态，训练时直接采样，可让策略专注学「怎么转」。

📖 本章术语速查

Grasp 环境
专门用来「筛成功握姿」的 Gym 任务，奖励恒为 0，不做 RL 训练。继承 Rotate 环境，只改成功判定和 reset。
Rotate 环境
正式训练 in-hand rotation 的环境，reset 时从缓存抽样起手式。
.npy 文件
NumPy 的二进制数组格式。本项目里是一张「行=姿态、列=28 个数」的表，用 np.load 读取。
scale bucket（尺寸桶）
圆柱直径 0.4–0.6 m 之间均匀 8 档；每档单独攒 6250 条姿态，最后纵向拼成 50000 行。
cond1 / cond2 / cond3
Grasp 环境每步检查的三个「握住了吗」条件；任一失败立刻 reset 重试。
zero_actions
全零动作向量：不主动下指令，只靠 PD 保持当前目标，让手和物体在重力下自然合拢。
episode_length
本局已走的控制步数。Grasp 里要撑满 399 步（20 s）且全程 cond 成立，才记入缓存。

零、把 .npy 想成 Excel 表

没用过 NumPy 的同学，可以把 cache/xhand_grasp_linspace_0.4-0.6-8.npy 想象成一张 Excel：
  • 行 = 一种「已成功抓住」的起手姿势（共约 50000 行）
  • 列 = 28 列数字：前 21 列手指关节角，22–24 列物体 xyz，25–28 列物体四元数
  • 工作表分页 = 8 个 scale bucket 纵向拼在一起：第 1–6250 行是细笔，6251–12500 是稍粗……
  • 训练 reset = 在对应分页里随机挑一行，照抄 28 个数到仿真里
np.load(...) 就像 pd.read_csv 一次性把整张表读进内存；torch.from_numpy 再拷到 GPU 上供并行 env 索引。
Excel 类比 ↔ 代码
Excel 概念代码对应本项目典型值

总列数d.shape[1]28

Q：为什么不直接存 CSV？
A：50000×28 的 float32 表 CSV 约几十 MB 且读写慢；.npy 二进制紧凑、np.load 一行代码，和 PyTorch 互转方便。你仍可用 python -c "import numpy as np; print(np.load(...)[0])" 窥一眼某行。

一、两个环境：Grasp vs Rotate

同一个 Xhand 手、同一根圆柱，但两个不同的 Gym 任务：Grasp 像「摄影师」——只负责拍几千张「握好了」的定格照存进相册；Rotate 像「杂技演员」——每次上台从相册抽一张照摆好姿势，然后学怎么转笔。

1. 奖励恒为 0

Rotate 环境的 _get_rewards() 计算角速度奖励、线速度惩罚、力矩惩罚等（见第 17 章）。Grasp 环境完全覆盖此方法，始终返回 0——这里不做 RL 训练，只筛「哪些姿态算成功抓住」。

xhand_wave_grasp_env.py · _get_rewards 末尾 
        if self.common_step_counter % 40 == 0:
            self.physics_sim_view.set_gravity(self.gravity_all_directions[self.gravity_id])
            self.gravity_id += 1
            self.gravity_id %= len(self.gravity_all_directions)
        return 0   # Grasp 环境不训练策略，奖励恒为 0
白话 walk-through · 奖励为 0 但仍每步 step
return 0PPO 不连上来——没有 loss、没有梯度。脚本只是 while True: env.step(zero)。
每 40 步换重力六向重力轮换，让同一姿势在 ±X/±Y/±Z 下都试过，相册里的行更「耐造」。
副作用：仍跑 cond 判定虽然奖励为 0，_get_rewards 里每步仍算 cond1/2/3，失败就 reset。

2. 成功条件 cond1 / cond2 / cond3（含具体数字）

每步检查三个条件，全部满足才算「这一拍握住了」。任一不满足则 reset_buf = 1，该 env 立刻重开。要连续 399 拍都成立，episode 结束才把 28 维写入缓存。

三个成功条件（阈值 + 数字举例）
代号判定式通过举例失败举例直觉
cond1
指尖距离		 5 指到物体中心距离均 < 0.1 m (10 cm) 拇指 0.062 m，食指 0.071 m，…，小指 0.088 m（都 < 0.1） 无名指 0.112 m → 哪怕其它四指都近，全体失败 五指围拢到物体附近，不是空手比划
cond2
接触力		 10 个接触传感器中 ≥ 3 个 法向力 > 0.5 N 传感器力 [0.8, 1.2, 0.6, 0.1, …] → 3 个 >0.5，通过 只有 2 个指 >0.5 N（其余 0.2 N）→ 算「靠近但没握紧」 要真在推物体，不是轻轻蹭到
cond3
姿态稳定		 物体相对默认姿态旋转角 < 30° ($\pi/6$) 相对默认只偏了 12° → 通过 物体翻滚了 45° → 握姿不可复现，丢弃 物体没有大幅翻滚，pose 可写入相册复用
一步仿真快照： 某 env 在 step 200：五指距离 [0.07, 0.08, 0.06, 0.09, 0.05] m → cond1 ✓。10 路力传感器范数 [1.1, 0.9, 0.7, 0.3, 0.2, 0.1, 0.4, 0.1, 0.0, 0.0] N → 前三个 >0.5，共 3 个 → cond2 ✓。物体相对默认转 8° → cond3 ✓。三条件都过，这一拍不算 reset；若下一步小指滑到 0.11 m → cond1 ✗ → 立刻 reset，本局前 200 步白跑。
xhand_wave_grasp_env.py · 成功判定核心 
finger_dist = torch.norm(self.fingertip_pos - self.object_pos.unsqueeze(1), dim=-1, p=2)
cond1 = (finger_dist < 0.1).all(-1)          # 5 指全部 < 10 cm

filtered_force_matrix = torch.cat([
    self._contact_sensor[id].data.force_matrix_w[:, 0, 0, :].unsqueeze(1)
    for id in range(10)
], dim=1)
finger_force = torch.norm(filtered_force_matrix, dim=-1, p=2)
cond2 = (finger_force > 0.5).sum(-1) >= 3    # 至少 3 个传感器 > 0.5 N

cond3 = torch.less(
    quat_to_rot(quat_mul(self.object_rot, quat_conjugate(self.object.data.default_root_state.clone()[:, 3:7]))),
    self.cfg.reset_angle_diff,               # 默认 30° = π/6
)
cond = cond1.float() * cond2.float() * cond3.float()
self.reset_buf[cond < 1] = 1                 # 任一失败 → 立刻 reset
白话 walk-through · cond 判定（逐行）
finger_dist shape (N, 5)每个并行 env 的 5 根指尖，各算到物体中心的欧氏距离 (m)。
(dist < 0.1).all(-1)all：5 个都要 <10 cm，有一个 10.1 cm 就挂。
10 个 contact_sensor比 Rotate 训练用的 5 个多——Grasp 用更密的力矩阵判「至少 3 点用力」。
(force > 0.5).sum(-1) >= 3数有几个传感器 >0.5 N；2 个不够，3 个够。
quat_to_rot(...) < 30°物体姿态相对 spawn 默认姿态偏了多少度；翻太大不要。
cond = c1 * c2 * c3三个都 1 才乘出 1；任何一个 0 就失败。
reset_buf[cond < 1] = 1失败的 env 标记要 reset——不等同于训练里的 height_reset，是 Grasp 专用早停。

脚本每 100 步打印失败统计，方便调参时看哪个条件卡得最狠：

[Fail Stats] steps=100 | cond1_fail=4200(42.0%) | cond2_fail=3100(31.0%) | cond3_fail=800(8.0%) | total_reset=6500(65.0%) | total_success=3500(35.0%)
[Dbg] per-finger avg dist to obj (thumb, index, mid, ring, pinky): [0.082, 0.091, 0.078, 0.095, 0.102] m  (cond1 needs all < 0.100)
[Dbg] per-finger avg contact force: [0.62, 0.55, 0.48, 0.31, 0.22] N  (cond2 needs ≥3 fingers > 0.500)
读日志：pinky avg dist 0.102 刚好超 0.1 → cond1 是常见瓶颈；ring 0.31 N 不够 0.5 → cond2 也紧。调参方向包括：默认手型更包拢、物体尺度、PD 刚度——但别轻易放宽阈值，否则相册里全是「假抓」。
Q：为什么要撑满 399 步才写入？瞬时不就行了吗？
A：瞬时满足 cond 可能是运气；连续 20 s（399 控制步）在六向重力轮换下都稳住，说明这个 pose 真的耐折腾。这是用仿真时间换缓存质量。

3. 六向重力轮换

Grasp 环境在 __init__ 里定义 6 个重力方向（±X、±Y、±Z），每 40 个仿真步切换一次。目的是让收集到的抓取姿态在不同重力朝向下都经受过考验，提高 sim-to-real 鲁棒性。

xhand_wave_grasp_env.py · gravity_all_directions 
self.gravity_all_directions = [
    carb.Float3(0.0,  0.0,  9.81),   # +Z 物体往下掉（相对手）
    carb.Float3(0.0,  0.0, -9.81),   # -Z（常规地球重力）
    carb.Float3(0.0,  9.81, 0.0),    # +Y
    carb.Float3(0.0, -9.81, 0.0),    # -Y
    carb.Float3(9.81,  0.0, 0.0),    # +X
    carb.Float3(-9.81, 0.0, 0.0),    # -X
]
白话 walk-through · 六向重力
每 40 control step 换一次399 步里大约换 10 次方向——同一局里物体「从不同方向拽手」。
±9.81 m/s²比训练初期 −0.05 的重力课程猛得多；Grasp 阶段就要硬扛地球重力。
写入缓存的是「全程存活」的 pose能通过 399 步 + 六向重力的人，才配进 Excel 表。

三、gen_grasp.py：无限循环收集

入口脚本极其精简——创建 Grasp 环境，发零动作，永远 step，直到缓存填满后环境内部 exit()。

scripts/gen_grasp.py · 主循环 
env = gym.make(args_cli.task, cfg=env_cfg, render_mode=None)
env = GymStyleEnvWrapper(env, clip_actions=env_cfg.clip_actions)

env.reset()
while True:
    actions = env.zero_actions()   # 全零动作：手保持当前 PD 目标
    _ = env.step(actions)
白话 walk-through · gen_grasp 主循环
gym.make(Grasp 任务)启动「摄影师」环境，不是训练任务。
zero_actions()21 维全 0 → 增量动作不改动目标 → 手维持当前姿势，靠重力让物体滚进掌心。

收集逻辑（Grasp 环境的 _reset_idx）

Grasp 环境覆盖了父类 _reset_idx，不走缓存采样，而是：

  1. 手从默认姿态 + 小随机扰动起步，物体从默认位置落下；
  2. 零动作下靠 PD 控制器和重力让手「自然」合拢；
  3. 若某 env 存活到 episode_length == max_episode_length - 1（399 步，且全程 cond1∧cond2∧cond3），把该瞬间的 28 维状态写入对应 scale bucket；
  4. 每个 bucket 攒满 5e4 // scale_num = 6250 条后标记完成；
  5. 8 个 bucket 全部完成 → 合并写入 .npy → exit()。
xhand_wave_grasp_env.py · 成功样本写入 bucket 
success = self.episode_length_buf == self.max_episode_length - 1
all_states = torch.cat([self.hand_dof_pos, self.object_pos, self.object_rot], dim=1)[success]
saved_scale_ids = self.scale_ids[success]

for id, saved_scale_id in enumerate(saved_scale_ids):
    cap = int(5e4 // self.cfg.scale_range[2])   # 每 bucket 上限 6250
    if self.saved_grasping_states[saved_scale_id].shape[0] < cap:
        self.saved_grasping_states[saved_scale_id] = torch.cat([
            self.saved_grasping_states[saved_scale_id],
            all_states[id].reshape(-1, self._grasp_state_dim)
        ], dim=0)

# 所有 bucket 满 → 保存并退出
if finish_scale == self.cfg.scale_range[2]:
    np.save(name, save_data.cpu().numpy())
    exit()

all_states 28 维cat 关节+物体位姿，就是 Excel 一行。
saved_scale_id这个 env 负责哪种直径的圆柱，就 append 到哪个 bucket 列表。

四、训练环境 _reset_idx 从缓存采样

Rotate 环境（正式训练）的 grasp_cache_path 非空时，reset 不再随机撒物体，而是从 .npy 随机抽一行，恢复手关节角和物体位姿。

把缓存想成一本「成功抓笔姿势相册」。每次有 env 需要 reset，就翻到对应尺寸（scale bucket）的某一页，照抄 28 个数。例如 env #3 分到最细圆柱（bucket 0），可能在第 42 行抽到一张「拇指弯 0.52 rad、物体 z=0.618 m」的定格照。
xhand_wave_env.py · 按 bucket 随机采样 
# pose cache
sampled_pose_idx = torch.randint(0, self.bucket_grasp, size=(self.bucket_env,))
saved_grasping_states_picked = torch.zeros((self.num_envs, self.num_hand_dofs + 7), device=self.device)
for i in range(self.cfg.scale_range[2]):
    saved_grasping_states_picked[i*self.bucket_env:(i+1)*self.bucket_env] = \
        self.saved_grasping_states[i*self.bucket_grasp:(i+1)*self.bucket_grasp][sampled_pose_idx]

sampled_pose = saved_grasping_states_picked[env_ids].clone()

# 用 sampled_pose 写回仿真
object_default_state[:, 0:3] = sampled_pose[:, 21:24] + self.scene.env_origins[env_ids]
object_default_state[:, 3:7] = sampled_pose[:, 24:28]
dof_pos = sampled_pose[:, :21]
self.hand.write_joint_state_to_sim(dof_pos, dof_vel, env_ids=env_ids)
白话 walk-through · 训练 reset 抽样（带数字）
num_envs=80, bucket_env=10每个尺寸 10 个并行 env；一次 reset 抽 10 个随机行号。
sampled_pose_idx = [42, 1088, 3, …]长度 10；bucket 0 的 env 用第 42 行，bucket 1 用 1088 行……
sampled_pose[env_ids]只对刚 done 的 env 操作；其它 env 继续转笔。
物体位置 + env_origins缓存里是局部坐标；写回仿真要加网格偏移，物体才出现在正确世界位置。
dof_pos 写回 hand21 个关节角瞬间设为相册里的值——开局就是「已抓住」。

注意两个约束：

  • num_envs 必须能被 scale_range[2]（bucket 数 8）整除，否则启动时报错退出；
  • 若 grasp_cache_path = None 或文件缺失，训练 reset 会 raise RuntimeError("No saved grasping states found")。
Q：训练时 height_reset 很频繁，是缓存坏了吗？
A：不一定。常见原因：① 缓存与当前 scale_range 不匹配（改了 cfg 没重跑 gen_grasp）；② 训练初期重力虽轻但策略乱动把笔弄掉；③ 高度窗 4 cm 太窄。先看 TensorBoard height_reset_*，再用 tryit 检查 .npy 是否存在且 shape 为 (50000, 28)。

七、常见问题（FAQ）

Q：gen_grasp 要跑多久？可以 Ctrl+C 吗？
A：RTX 5070 Ti、num_envs≈几十时常见 5–15 分钟。中途 Ctrl+C 不会保存完整 .npy（只有满 8 bucket 才 write）。断了就重新跑，或接受不完整缓存（训练会缺行）。
Q：cond2 为什么用 10 个传感器而不是 5 个？
A：Xhand URDF 里部分指尖有多个碰撞 patch；Grasp 用更密的 force_matrix_w 判「至少 3 点用力」，比单点力更稳。Rotate 训练观测仍用 5 维触觉（对应 5 个 dip 传感器）。
Q：能不能手工编辑 .npy 某一行？
A：可以 d = np.load(...); d[42, 21:24] = [...]; np.save(...)，但不推荐——没经过 cond 筛选的行可能导致 reset 后立刻 height_reset。应用 gen_grasp 自动收集。
Q：50000 行够不够？
A：对 10–80 个并行 env 通常足够：每个 bucket 6250 种起手式，重复率不高。若你发现 TensorBoard 里同一 grasp pose 出现太频繁，可改 cfg 把 5e4 加大后重跑 gen_grasp（会线性变慢）。
与 16 章的衔接： Rotate 环境 __init__ 把整张 Excel 读进 saved_grasping_states；_reset_idx 按 scale_ids 抽行写回仿真。读 16 章 buffer 表时若疑惑「相册从哪来」，就是本章 gen_grasp 的产物。

本章小结。 Grasp 环境奖励为 0，用 cond1（5 指 <10 cm）、cond2（≥3 点 >0.5 N）、cond3（姿态 <30°）筛成功姿态，六向重力增鲁棒性。.npy 就是 50000×28 的 Excel 表。gen_grasp.py 零动作无限循环直到缓存满。训练环境从同名文件按 bucket 随机抽行作为 episode 起点。下一章看 wrapper 如何把环境观测递给 PPO。
