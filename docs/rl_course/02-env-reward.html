CHAPTER 02 · 把抽象变具体

本项目的 MDP 与奖励塑形

观测、动作到底是哪些数字？奖励为什么要拆成六项？这一章把第 01 章的符号全部"通电"。

代码详解。 本章讲概念与公式；对应源码见 Part B：第 16 章（环境生命周期）、第 17 章（观测/奖励逐行）。

一、任务一句话

让机械手把手心里的圆柱体，绕一个固定的轴（默认是竖直的 z 轴）不停地往一个方向转，而且别把它转掉、转飞、或者把手指拧到极限。转得越顺，给的分越高；动作太猛、太费力、物体乱跑，就扣分。

二、动作空间 A：21 个关节

动作是一个 21 维向量 $a_t\in[-1,1]^{21}$，每一维对应一个被驱动的手指关节（拇指、食指、中指、无名指、小指共 21 个自由度）。

关键点：动作不是直接的关节角度，而是"在上一时刻目标基础上的增量"。这叫增量位置控制（relative target）：

$$\text{target}_t \;=\; \text{target}_{t-1} \;+\; \alpha \cdot a_t, \qquad \alpha = \tfrac{1}{24}\ (\text{action\_scale}).$$

然后把目标"夹"在关节物理上下限内（saturate），再喂给力矩控制器。

xhand_wave_env.py · _pre_physics_step 
actions = saturate(actions, -clip_actions, clip_actions)   # 先裁到 ±1
targets = self.prev_targets + self.cfg.action_scale * self.actions
self.cur_targets[:, idx] = saturate(targets, lower, upper)  # 再裁到关节限位
为什么用"增量"而不是"绝对角度"？因为一个网络直接输出 0.73 弧度这种绝对值很难学，而输出"再多弯一点 / 松一点"这种相对微调既平滑又安全，天然限制了每步的动作幅度（最多 ±1/24 弧度）。

力矩控制：动作如何变成力

目标位置确定后，底层用 PD 控制器算出每个关节真正施加的力矩：

$$\tau \;=\; k_p\,(\,\text{target} - q\,) \;-\; k_d\,\dot q.$$
符号表 · PD 控制
符号含义
$\tau$关节力矩（代码 self.torques）。
$k_p$比例增益（刚度），"离目标越远，拉力越大"。代码 p_gain。
$k_d$微分增益（阻尼），"动得越快，越踩刹车"，防止抖动。代码 d_gain。
$q,\ \dot q$当前关节角度与角速度。

$k_p,k_d$ 在每局重置时会被随机扰动（域随机化，见第 09 章），逼策略学会"对不同手感都鲁棒"。

三、观测空间 S：186 维是怎么拼的

策略每步看到的观测是 186 维。它由"单帧 62 维 × 最近 3 帧"堆成：

$$\underbrace{186}_{\text{observation\_space}} \;=\; \underbrace{62}_{\text{单帧}} \times \underbrace{3}_{\text{帧}}, \qquad 62 = \underbrace{21}_{\text{关节角}} + \underbrace{21}_{\text{控制目标}} + \underbrace{5}_{\text{指尖触觉}} + \underbrace{15}_{\text{接触点}}.$$
符号表 · 单帧观测的四块
分量维度含义
归一化关节角 $\hat q$21当前 21 个关节角度，按限位归一化到 ±1（含小噪声，模拟编码器误差）。
当前控制目标21这一步发出去的目标位置，让策略"知道自己刚才下了什么命令"。
指尖触觉力5五个指尖的接触力大小（平滑+延迟+噪声后的值）。
接触点位置155 指 × 3 维接触点坐标（默认关闭，置零占位）。
为什么要 3 帧？ 单看一帧只知道"现在手在哪"，看不出"在怎么动"。叠加最近 3 帧，网络就能感知速度和趋势——这正是为了满足第 01 章说的马尔可夫性，把"决定未来所需的信息"塞进状态。
此外还有一份更长的 30 帧历史（proprio_hist），它不给教师用，而是留给第二阶段的 TConv 适配模块（第 06 章）。
xhand_wave_env.py · compute_observations（节选） 
# 把【归一化关节角(带噪) + 目标 + 触觉 + 接触点】拼成单帧，压入滑动窗口
cur_obs_buf = unscale(joint_noise + hand_dof_pos, lower, upper).unsqueeze(1)
cur_obs_buf = torch.cat([cur_obs_buf, cur_targets, sensed_contacts, contact_pos], dim=-1)
self.obs_buf_lag_history = torch.cat([prev_obs_buf, cur_obs_buf], dim=1)
obs_buf = self.obs_buf_lag_history[:, -3:].reshape(num_envs, -1)   # 最近 3 帧 → 186 维
关于维度数字的脚注。 本章数字取自当前代码 xhand_wave_env_cfg.py（action_space=21, observation_space=186, prop_hist_len=30）。项目 CLAUDE.md 的对照表写的是 12/132，那是另一套精简变体；以你实际要跑的 cfg 为准即可，原理完全一致。

四、奖励 R：六项的合奏

这是本章的重头戏。总奖励是六项的加权和，每一项管一件事。先看总公式，再逐项拆。

$$r \;=\; w_{\text{rot}}\, r_{\text{rot}} \;+\; w_{\text{lin}}\, p_{\text{lin}} \;+\; w_{\text{pos}}\, p_{\text{pos}} \;+\; w_{\tau}\, p_{\tau} \;+\; w_{\text{wk}}\, p_{\text{wk}} \;+\; w_{\text{op}}\, r_{\text{op}}.$$
xhand_wave_env.py · compute_rewards（torch.jit） 
reward  = rotate_reward          * rotate_reward_scale        #  +2.5
reward += object_linvel_penalty  * object_linvel_penalty_scale #  -0.3
reward += pos_diff_penalty       * pos_diff_penalty_scale      #  -0.4
reward += torque_penalty         * torque_penalty_scale        #  -0.1
reward += work_penalty           * work_penalty_scale          #  -0.5
reward += object_pos_diff        * object_pos_reward_scale      # +0.003

① 旋转奖励 r_rot（主菜，唯一的正向驱动）

先用相邻两帧的四元数差，算出物体的角速度，再把它投影到目标旋转轴上，最后裁剪：

$$\omega \;=\; \frac{\mathrm{axisangle}\big(q_t \otimes q_{t-1}^{-1}\big)}{\Delta t}, \qquad r_{\text{rot}} \;=\; \clip\!\big(\,\omega \cdot \hat n,\; -0.5,\; 0.5\,\big).$$
符号表 · 旋转奖励
符号含义
$q_t, q_{t-1}$物体本帧/上帧的姿态四元数。
$\otimes$四元数乘法；$q_t\otimes q_{t-1}^{-1}$ 表示"这一帧相对上一帧转了多少"。
$\mathrm{axisangle}(\cdot)$把四元数转成"轴×角"向量，方向是转轴、长度是转角。
$\Delta t$一个控制步的时长（代码 step_dt）。除以它就得到角速度。
$\hat n$目标旋转轴单位向量（rot_axis，默认 $(0,0,1)$）。点积 $\omega\cdot\hat n$ = 沿目标轴的角速度分量。
$\clip(\cdot,-0.5,0.5)$把奖励夹在 ±0.5，防止"猛甩一下骗高分"，鼓励持续平稳旋转。
点积 $\omega\cdot\hat n$ 的妙处：往正确方向转，分量为正、加分；往反方向转，分量为负、变成惩罚；绕错误的轴乱晃（比如让物体点头而不是转圈），在目标轴上的投影几乎为 0，没分。一个点积就同时管了"方向对不对"和"快不快"。

②~⑤ 四个惩罚项（负权重，教它"优雅地"转）

项公式管什么
线速度惩罚 $p_{\text{lin}}$$\dfrac{\lVert x_t - x_{t-1}\rVert_1}{\Delta t}$物体质心别乱平移（只许转、不许跑）。
姿态偏离惩罚 $p_{\text{pos}}$$\sum_i (q_i - q_i^{\text{default}})^2$手指别离"自然抓握姿态"太远，避免拧到奇怪构型。
力矩惩罚 $p_{\tau}$$\sum_i \tau_i^2$别用蛮力，省电、保护电机。
做功惩罚 $p_{\text{wk}}$$\big(\sum_i \tau_i\,\dot q_i\big)^2$惩罚"功率"（力矩×速度），让动作更节能更平滑。

这四项权重都是负数，所以它们越大、总奖励越低。它们不教手"怎么转"，而是约束手"别太用力、别乱动"——这对 sim-to-real 至关重要，因为蛮力动作在真机上往往直接失败。

⑥ 位置保持奖励 r_op（防掉落的小奖励）

$$r_{\text{op}} \;=\; \frac{1}{\lVert x_t - x^{\text{default}}\rVert + 0.001}.$$

物体离初始位置越近，这个值越大（分母越小）。它温柔地把物体"吸"在手心中央，权重很小（0.003），只起辅助作用。加 0.001 是为了防止分母为零。

奖励项权重调节器
拖动六个权重，看每一项对总奖励的贡献（绿色加分、红色扣分）。下面用一组"典型时刻"的原始值演示——这正是调参工程师每天在做的事。
奖励塑形（reward shaping）的哲学。 只给"转得快"一项奖励，策略会学出疯狂甩手的暴力解；加上四个惩罚和一个保持项，才把它逼向"又快又稳又省力又不掉"的优雅解。设计奖励就是设计目标本身——这是强化学习里最需要经验、也最像艺术的一步。

五、终止条件：什么时候这一局结束

两种情况会重置环境（对应 _get_dones）：

  • 物体掉了：物体高度超出 [下限, 上限]（掉出手心或被顶飞）。
  • 超时：达到本局最大步数（episode 时长 20 秒）。这种"超时"会被特殊处理（value bootstrap，见第 04 章），因为它不代表"做错了"。

这里还藏着一个重力课程：当几乎没人再掉物体时，自动把重力调大一点点，逐步加难度（详见第 09 章）。
