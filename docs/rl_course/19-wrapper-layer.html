CHAPTER 19 · 环境与算法的桥梁

Wrapper 适配层

IsaacLab 的 DirectRLEnv 返回 Gymnasium 风格的 dict 观测；PPO 算法期望的是 RSL-RL 风格的 VecEnv 接口。本章精读 GymStyleEnvWrapper 和 vec_env.py，弄清观测字典如何流到 model_act。

为什么需要 Wrapper？ IsaacLab 环境已经很好，但它的 step() 返回 terminated | truncated 两个布尔张量，观测藏在 obs_dict["policy"] 里，还有 priv_info、proprio_hist 等额外键。PPO（源自 RLGames/RSL-RL 传统）期望统一的 VecEnv 接口：dones 合并、extras["observations"] 携带副观测。Wrapper 做这一层「格式翻译」，算法代码不用改。

本章术语表（零基础版）

Wrapper（包装器）
套在环境外面的一层「翻译官」，不改仿真逻辑，只改接口格式。PPO 永远只跟 Wrapper 说话，不直接碰 IsaacLab。
VecEnv
向量化环境抽象类：一次 step 同时推进 N 个并行仿真（num_envs 个）。RSL-RL 系算法约定必须实现 reset / step / get_observations。
obs_dict
观测字典，键名如 policy、priv_info、proprio_hist。Wrapper 额外加别名 obs，方便 PPO 统一读取。
terminated / truncated
Gymnasium 新标准：前者=任务真正失败/成功结束；后者=时间到了被截断。Wrapper 用 | 合并成 dones。
priv_info（特权信息）
仿真里才能直接读到的「上帝视角」：物体偏移、质量、摩擦等。真机没有，Stage 2 用 TConv 从历史猜。
proprio_hist
过去 30 步的本体感知滑动窗口，形状 (N, 30, 62)。Stage 1 PPO 不用，Stage 2 蒸馏专用。
clip_actions
动作裁剪上限，Xhand 默认 1.0。策略采样可能超出范围，Wrapper 在进仿真前 clamp。
time_outs
因达到 max_episode_length 被截断的 mask，不是真正失败。PPO 用它做 value bootstrap。

零、把 Wrapper 想成「两种语言的翻译官」

想象两个部门：IsaacLab 仿真部说「Gymnasium 方言」——step 返回五个东西 (obs_dict, reward, terminated, truncated, info)，观测键叫 policy；PPO 算法部说「RSL-RL 方言」——要四个东西 (obs, reward, dones, extras)，还要 extras["observations"] 里塞完整副观测。

GymStyleEnvWrapper 就是坐在中间的同声传译：仿真部说什么，它翻译成算法部能听懂的格式；算法部下指令，它再翻回去传给仿真。你改 IsaacLab 环境时，只要 Wrapper 这层翻译规则不变，PPO 一行都不用动——这就是 Wrapper 存在的全部理由。
IsaacLab 说的（源语言）Wrapper 翻译后（目标语言）
obs_dict["policy"]再加别名 obs_dict["obs"]，PPO 读 self.obs['obs']
terminated 与 truncated 分开dones = (terminated | truncated).long()
副观测散落在 dict 各键extras["observations"] = obs_dict 整包备份
无限 horizon 任务的截断extras["time_outs"] = truncated
动作可能越界torch.clamp(actions, ±clip_actions) + 改 Box 边界
问：为什么不直接改 PPO 去适配 Gymnasium？ 可以，但 PPO 代码来自 RLGames/RSL-RL 生态，改算法意味着以后升级 IsaacLab 官方 wrapper 时对不上。改一层 Wrapper 成本最低，也是 IsaacLab 官方推荐做法。

一、Wrapper 在流水线中的位置

train.py 创建环境后立刻包一层 GymStyleEnvWrapper，之后 PPO 只跟 wrapper 对话，不再直接接触 IsaacLab 环境。顺序固定：gym.make → Wrapper → PPO，中间不能插别的。

二、VecEnv 抽象接口

vec_env.py 定义了向量化环境必须实现的三个方法，以及 extras 字典的约定。它本身不干活，只规定「翻译官必须会哪些句式」。

wrapper/vec_env.py · 核心抽象方法 
class VecEnv(ABC):
    num_envs: int
    num_actions: int
    max_episode_length: int | torch.Tensor
    episode_length_buf: torch.Tensor
    device: torch.device
    cfg: dict | object

    @abstractmethod
    def get_observations(self) -> tuple[torch.Tensor, dict]: ...

    @abstractmethod
    def reset(self) -> tuple[torch.Tensor, dict]: ...

    @abstractmethod
    def step(self, actions: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor, dict]:
        """返回 (obs, rewards, dones, extras)"""
VecEnv 三个抽象方法 · 各自干什么
方法白话
reset()所有并行 env 一起回到 episode 起点。返回当前观测 dict（含 policy / priv_info 等）。
step(actions)把形状 (N, 21) 的动作张量送进仿真，推进一步物理，返回 obs、reward、dones、extras。
get_observations()只读当前观测、不 step。play 脚本暂停调试时用。
extras 字典保留键
键类型用途
"observations"dict[str, Tensor]副观测：critic、priv_info、proprio_hist 等完整备份
"time_outs"Tensor因超时（非真正终止）结束的 mask，用于 value bootstrap
"log"dict调试/日志标量
问：extras 和 obs_dict 有什么区别？ step 的第一个返回值就是完整 obs_dict（PPO 赋给 self.obs）。extras["observations"] 是同一份 dict 的副本，供 RSL-RL 生态里其他模块（如 asymmetric critic）按约定读取。本项目 PPO 主要直接用第一个返回值。

三、GymStyleEnvWrapper 初始化

构造时从底层环境读取维度信息，修改 action space 裁剪范围，并主动调用一次 reset（因为 RSL-RL 风格的 runner 不会在创建后自动 reset）。

sharpa_wave_env_wrapper.py · __init__（节选） 
class GymStyleEnvWrapper(VecEnv):
    def __init__(self, env, clip_actions):
        self.env = env
        self.clip_actions = clip_actions

        self.num_envs = self.unwrapped.num_envs
        self.device = self.unwrapped.device
        self.max_episode_length = self.unwrapped.max_episode_length
        self.prop_hist_len = self.unwrapped.cfg.prop_hist_len

        # 动作维：Xhand = 21
        self.num_actions = gym.spaces.flatdim(self.unwrapped.single_action_space)
        # 策略观测维：Xhand = 186
        self.num_obs = gym.spaces.flatdim(self.unwrapped.single_observation_space["policy"])

        self._modify_action_space()   # 按 clip_actions 改 Box 上下界
        self.env.reset()              # 构造时立刻 reset 一次
__init__ 逐行 · 翻译官上岗 checklist
代码白话
isinstance(env.unwrapped, DirectRLEnv)类型检查：只接受 IsaacLab 的 DirectRLEnv / ManagerBasedRLEnv，别的 Gym 环境会报错。
self.num_envs / device从底层抄并行数与 GPU 设备号，PPO 据此分配张量。
self.prop_hist_len历史窗口长度（30），ProprioAdapt 初始化 sa_mean_std 时用。
flatdim(single_action_space)单 env 动作维数 → Xhand 21。再 batch 成 (N, 21)。
flatdim(...["policy"])策略观测维 → Xhand 186（3 帧 × 62 维单帧）。
_modify_action_space()把 Gym Box 的 low/high 改成 ±clip_actions，让 PPO 知道合法范围。
self.env.reset()关键：构造完立刻 reset，否则第一次 play_steps 拿到的是未初始化观测。
初始化末尾那次 reset() 很容易被忽略：RSL-RL 的 train() 里也会 self.obs = self.env.reset()，但 Wrapper 构造时已经 reset 过一次，保证环境内部 buffer（proprio_hist、priv_info 等）处于合法状态。双 reset 无害，第二次 reset 会覆盖为正式训练起点。

四、reset()

调用底层 env.reset()，拿到 IsaacLab 的观测 dict，添加别名键 "obs" 指向 "policy"，方便 PPO 统一用 obs_dict['obs']。

sharpa_wave_env_wrapper.py · reset 
def reset(self) -> tuple[torch.Tensor, dict]:
    obs_dict, _ = self.env.reset()
    obs_dict["obs"] = obs_dict["policy"]   # 别名：PPO 读 obs_dict['obs']
    return obs_dict
reset() 三行 · 翻译过程
代码白话
obs_dict, _ = self.env.reset()调用 IsaacLab 原生 reset。第二个返回值 info 被丢弃（本项目不用）。
obs_dict["obs"] = obs_dict["policy"]加别名：算法侧统一读 obs，不必记 IsaacLab 的 policy 键名。
return obs_dict返回整个 dict（不是单独 tensor）。PPO 的 self.obs 就是这个 dict。

此时 obs_dict 的键来自环境 _get_observations()：

xhand_wave_env.py · _get_observations 
def _get_observations(self) -> dict:
    obs = self.compute_observations()      # shape (num_envs, 186)
    return {
        "policy": obs,
        "priv_info": self.priv_info_buf,    # shape (num_envs, 8)
        "proprio_hist": self.proprio_hist_buf,  # shape (num_envs, 30, 62)
    }
问：为什么 reset 返回 dict 而不是 (obs, info) 元组？ 这是 RSL-RL VecEnv 约定，不是 Gymnasium 标准。PPO 代码写死了 self.obs['obs'] 这种访问方式；Wrapper 负责把 IsaacLab 的输出「翻译」成这种形状。

五、step() 与 clip_actions

1. 动作裁剪

策略网络输出未经约束的高斯采样动作，wrapper 在送入仿真前用 torch.clamp 限制到 [-clip_actions, +clip_actions]（Xhand 默认 clip_actions = 1.0）。

sharpa_wave_env_wrapper.py · step 前半 
def step(self, actions: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor, dict]:
    if self.clip_actions is not None:
        actions = torch.clamp(actions, -self.clip_actions, self.clip_actions)
    obs_dict, rew, terminated, truncated, extras = self.env.step(actions)
step() 前半 · 动作进仿真前
代码白话
torch.clamp(actions, ...)把每个关节指令夹到 [-1, 1]。高斯采样可能到 ±3，不 clamp 会触发仿真异常或饱和。
self.env.step(actions)调用 IsaacLab 五步返回：obs_dict, rew, terminated, truncated, extras（Gymnasium 方言）。

初始化时同步修改了 Gym action space 的 Box 边界，让 PPO 知道合法范围：

sharpa_wave_env_wrapper.py · _modify_action_space 
self.env.unwrapped.single_action_space = gym.spaces.Box(
    low=-self.clip_actions, high=self.clip_actions, shape=(self.num_actions,)
)
self.env.unwrapped.action_space = gym.vector.utils.batch_space(
    self.env.unwrapped.single_action_space, self.num_envs
)

2. dones 合并与 extras 填充

sharpa_wave_env_wrapper.py · step 后半 
    dones = (terminated | truncated).to(dtype=torch.long)
    obs_dict["obs"] = obs_dict["policy"]
    extras["observations"] = obs_dict          # 完整观测 dict 塞进 extras
    if not self.unwrapped.cfg.is_finite_horizon:
        extras["time_outs"] = truncated        # 超时 mask → value bootstrap
    return obs_dict, rew, dones, extras
step() 后半 · 翻译回 RSL-RL 方言
代码白话
dones = (terminated | truncated).long()两个 bool 合并成一个 long 张量。任一为 True → done=1。
obs_dict["obs"] = obs_dict["policy"]每步都加别名，与 reset 一致。
extras["observations"] = obs_dict整包观测备份进 extras，RSL-RL 约定格式。
extras["time_outs"] = truncated仅无限 horizon 任务（手内旋转）。截断≠失败，PPO 要据此 bootstrap 价值。
return obs_dict, rew, dones, extras四元组返回。注意第一个仍是 dict，不是 tensor。

注意：wrapper 的 step 返回的第一个值是完整 obs_dict（不是单独的 policy tensor），PPO 直接把它赋给 self.obs。

问：PPO 里又 clamp 一次 actions，和 Wrapper 重复吗？ 略有冗余但无害。Wrapper 保证进仿真的动作合法；PPO 在 play_steps 里再 clamp 到 [-1,1] 是历史习惯，与 clip_actions=1.0 时效果相同。

六、三类「额外观测」详解

obs_dict 各键在训练中的角色
键Shape (Xhand)内容谁消费
obs / policy (N, 186) 3 帧堆叠的本体感知：关节角、目标、接触、接触位置 PPO Actor / Critic 主输入
priv_info (N, 8) 特权信息：物体相对位移、摩擦、质量、质心偏移等（仿真专属） Stage 1 PPO 的 env_mlp 嵌入
proprio_hist (N, 30, 62) 过去 30 步的单帧 proprio（186÷3=62）滑动窗口 Stage 2 ProprioAdapt 的 adapt_tconv
可以把 obs_dict 想成三个信封一起递给 PPO：obs 是「当前看到的」（主信）；priv_info 是「上帝小抄」（仅仿真有）；proprio_hist 是「过去 30 帧日记」（Stage 2 才拆封）。Wrapper 不做内容修改，只保证三个信封都送到、且贴上 obs 统一标签。

七、数据流：IsaacLab obs dict → PPO model_act

一步训练采集的数据路径：环境算观测 → wrapper 打包 → PPO 存 rollout → model_act 喂网络。关键是 wrapper 返回的 obs_dict 被 PPO 原样持有，model_act 从中拆出 obs 和 priv_info。 
IsaacLab DirectRLEnv
  │
  │  _get_observations() → {"policy", "priv_info", "proprio_hist"}
  │
  ▼
GymStyleEnvWrapper
  │
  │  reset()/step(): 添加 obs_dict["obs"] = obs_dict["policy"]
  │                  extras["observations"] = obs_dict
  │                  extras["time_outs"] = truncated (若无限 horizon)
  │
  ▼
PPO.play_steps()
  │
  │  model_act(self.obs)          ← self.obs 就是 wrapper 返回的 obs_dict
  │  env.step(actions)            ← 返回新 obs_dict 赋回 self.obs
  │  storage.update_data('obses', ..., self.obs['obs'])
  │  storage.update_data('priv_info', ..., self.obs['priv_info'])
  │
  ▼
ActorCritic.act(input_dict)
  │
  │  env_mlp(priv_info) → extrin → cat 到 obs → actor_mlp → 动作分布

八、与标准 Gymnasium 接口的差异

项标准 Gymnasium本项目 Wrapper + PPO
reset 返回值(obs, info)整个 obs_dict（含多键）
step 返回值obs, reward, terminated, truncated, infoobs_dict, reward, dones, extras
done 信号两个 bool合并为 dones: LongTensor
副观测放在 infoobs_dict 直接携带 + extras["observations"] 备份
动作裁剪环境内部或策略侧wrapper clamp + 改 action_space
构造后 reset由调用方决定Wrapper __init__ 末尾自动 reset 一次

九、get_observations() 辅助方法

除 reset/step 外，wrapper 还提供 get_observations()，供需要「只读当前观测、不 step」的场景（如 play 脚本中途暂停）：

sharpa_wave_env_wrapper.py 
def get_observations(self) -> tuple[torch.Tensor, dict]:
    obs_dict = self.unwrapped._get_observations()
    return obs_dict["policy"], {"observations": obs_dict}
get_observations · 与 reset 的区别
方法是否改环境状态返回值
reset()是，episode 重启完整 obs_dict（含 obs 别名）
get_observations()否，只读当前帧(policy_tensor, {"observations": obs_dict})
step()是，推进一步物理四元组 obs_dict, rew, dones, extras

十二、Stage 2 蒸馏时 Wrapper 有变化吗？

没有。 ProprioAdapt 同样用 GymStyleEnvWrapper 包环境。区别在算法侧：padapt.train() 的 input_dict 多了 proprio_hist，但 Wrapper 的 step/reset 行为与 Stage 1 完全一致——仍然返回含 priv_info 的 obs_dict（仿真里 priv 当 label）、仍然合并 dones、仍然写 time_outs。

十三、常见问题 FAQ

问：Wrapper 会拖慢训练吗？ 几乎不会。它只是几次张量操作（clamp、别名、布尔合并），耗时相对 PhysX 物理可忽略。
问：我能跳过 Wrapper 直接用 IsaacLab 环境吗？ 可以写新算法适配 Gymnasium 五步 API，但现有 PPO / ProprioAdapt 都写死了 VecEnv 接口，跳过 Wrapper 等于重写算法入口。
问：proprio_hist 在 Stage 1 占显存吗？ 占。环境每步都维护 (N, 30, 62) buffer，但 PPO 的 model_act 不读它。这是为 Stage 2 蒸馏预留的数据，避免换阶段时改环境。
问：文件名为什么叫 sharpa_wave_env_wrapper？ 历史命名，从 SharpaWave 模板继承。Xhand 任务同样使用这个 Wrapper，无需另写。

十四、张量 dtype 与 device 约定

Wrapper 边界上的 dtype
张量dtypedevice
actions 输入 stepfloat32与 env 相同（通常 cuda:0）
obs_dict 各值float32GPU，IsaacLab 直接写 CUDA tensor
donesint64 (long)GPU；RLGames 传统用 long 而非 bool
rewardsfloat32GPU，(N,) 或 (N,1) 视 PPO unsqueeze
问：dones 为什么是 long 不是 bool？ 历史 RLGames/RSL-RL 代码用 0/1 整数与 float 做 1.0 - dones 运算。Wrapper 用 .to(dtype=torch.long) 保持兼容。
Gym 的 observation_space 描述 policy 键的 Box shape (186,)。但 PPO 实际用的是 wrapper 返回的整个 dict，不是 gym.spaces 里注册的 flat tensor。别被 self.env.observation_space 迷惑——它主要用于 PPO 读 shape[1] 定 obs_dim。

问：clip_actions=None 时会怎样？ _modify_action_space 直接 return，不 clamp 动作也不改 Box。Xhand 默认 cfg 里 clip_actions=1.0，一般不设 None。
问：extras 里还会有别的键吗？ IsaacLab 环境可能在 info/extras 里放日志标量（如 episode reward）。PPO play_steps 末尾会把 float/int 标量抄进 self.extra_info 写 TensorBoard。Wrapper 不过滤这些键，原样传递。
问：ManagerBasedRLEnv 和 DirectRLEnv 都能包吗？ 能。Wrapper 的 type check 接受两者。本项目 Xhand 任务用 DirectRLEnv；若观测来自 observation_manager，get_observations 会走 observation_manager.compute() 分支。

本章小结。 VecEnv 定义算法期望的向量化接口；GymStyleEnvWrapper 像两种语言的翻译官，把 IsaacLab 环境翻译成该接口：reset/step 添加 obs 别名、合并 dones、裁剪动作、把完整 obs dict 塞进 extras。PPO 的 self.obs 就是这份 dict，model_act 读取 obs（186 维策略输入）和 priv_info（8 维特权嵌入）；proprio_hist 留给 ProprioAdapt。下一章进入 PPO 训练循环本体。
