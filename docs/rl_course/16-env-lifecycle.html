xhand_wave_env.py 生命周期逐行导读

读完本章，你能回答：IsaacLab DirectRLEnv 一步 control step 里，哪些回调按什么顺序被调用？__init__ 里预分配了哪些 buffer？重置时抓取缓存怎么采样？——即使你是第一次看 Python RL 代码，也能跟着「游戏循环」类比走完全程。

前置阅读。 第 02 章 讲了 MDP 直觉；第 15 章 讲了 xhand_wave_env_cfg.py 怎么被 Hydra 加载。本章聚焦环境类本身——rl_isaaclab/tasks/inhand_rotate/xhand_wave_env.py 里的 XhandWaveInhandRotateEnv。

📖 本章术语速查（先扫一眼，后面会反复用到）

DirectRLEnv
IsaacLab 的「直接 RL 环境」基类。奖励、观测、终止条件都在子类里手写 Python，不走 Manager 配置表。本项目的环境类继承它。
control step（控制步）
策略每 0.05 秒（20 Hz）调用一次 env.step(action)。内部会跑 decimation=12 次物理子步（240 Hz），才凑成这一拍。
buffer（缓冲区）
在 GPU 上预先分配好的张量，用来存「上一步关节角」「物体位置」等。训练时反复读写，避免每步 malloc 拖慢仿真。
hook（钩子函数）
父类在固定时机调用的子类方法，如 _pre_physics_step、_get_rewards。你只实现钩子，不 override step() 本身。
num_envs
并行仿真的环境个数。RTX 5070 Ti 12GB 建议从 10 起步；每个 env 是网格里独立的一格，有自己的 env_origins 偏移。
decimation
一个控制步里物理引擎跑几次。cfg 默认 12：策略说一次「动」，仿真内部算 12 次碰撞和接触。
grasp cache
预生成的「已成功抓住」起手姿态，存成 .npy。reset 时随机抽一行，让 episode 从「已握笔」开始（详见18 章）。
域随机化（DR）
启动或 reset 时随机改摩擦、质量、PD 增益等，让策略见过更多「假世界」，部署到真机更稳（09 章）。

零、把 DirectRLEnv 想成游戏主循环

如果你玩过《塞尔达》或任何 3D 动作游戏，DirectRLEnv 就是游戏引擎的主循环，只不过「玩家」换成了 PPO 神经网络：
  • 加载关卡 = __init__ + _setup_scene（搭手、圆柱、地面、复制 num_envs 份）
  • 读手柄输入 = step(action) 收到 21 维动作向量
  • 处理输入 = _pre_physics_step（裁剪动作 → 算关节目标位）
  • 物理演算 ×12 = Isaac Sim 内部碰撞、接触、重力（玩家看不见，但手指真的在推物体）
  • 驱动物体 = _apply_action（PD 力矩写进电机）
  • 读传感器 = _get_observations（关节角、触觉力 → 186 维向量）
  • 算分数 = _get_rewards（转得快加分、乱晃扣分）
  • 判断 Game Over = _get_dones（物体掉了？时间到了？）
  • 重开一局 = _reset_idx（从抓取缓存抽新手势）
PPO 从不直接调用 Isaac API——它只跟「车间主任」XhandWaveInhandRotateEnv 对话。主任内部再跟仿真引擎打交道。
Q：为什么不自己写 step()，只靠这些钩子？
A：IsaacLab 父类已经写好了「物理子步循环 + 计时 + episode 计数 + 自动 reset」的样板代码。子类只填「这一步具体算什么奖励、什么观测」，避免每个任务重复造轮子。改顺序或漏调某个钩子，训练会 silently 跑偏——所以本章把时间线画清楚。

二、DirectRLEnv 回调顺序（一生 + 一步）

2.1 诞生：从构造到第一帧

对象创建时，IsaacLab 父类会按固定顺序调用子类钩子。对我们最重要的是：

生命周期时间线
阶段调用做什么
① 子类预备__init__ 开头分配 reset_height_lower/upper 零张量（须在 super().__init__ 前，因父类会触发 reset）
② 父类构造super().__init__(cfg, ...)创建 SimulationContext、Scene；内部调用 _setup_scene()；首次 _reset_idx
③ 子类收尾__init__ 后半自检、buffer、抓取缓存、域随机化、接触传感器索引
④ 训练循环每 control step见下图：_pre_physics_step → 物理 × decimation → _apply_action → 观测/奖励/终止
⑤ 局末_reset_idx(env_ids)对 done 的环境重新采样抓取姿态、随机化 PD、写回仿真
为什么 reset_height_* 必须在 super().__init__ 之前？ 父类构造时会立刻做一次 reset，而 reset 逻辑要往 reset_height_lower[env_ids] 写本局高度窗口。如果张量还不存在，Python 会 AttributeError。这是新手读代码时最容易漏掉的一行「顺序陷阱」。
一步 control step 内部顺序
鼠标悬停各框可看函数名。decimation=12 时，中间「physics」会跑 12 次仿真子步（240 Hz），才凑成一个 20 Hz 控制步。

注意：step(action) 的入口在父类 DirectRLEnv。子类不 override step，只实现下面六个钩子（加上 _setup_scene 和 _reset_idx）：

  1. _pre_physics_step(actions) — 裁剪动作、算目标位、可选外力扰动
  2. 物理引擎 × decimation（cfg 里 = 12）
  3. _apply_action() — PD 力矩或位置目标写入仿真
  4. _get_observations() — 拼 186 维 policy obs + priv_info + proprio_hist
  5. _get_rewards() — 六项奖励（详见第 17 章）
  6. _get_dones() — 高度终止 + 超时 + 重力课程
白话 walk-through · 一步 step 像打游戏的一帧
PPO 输出 action神经网络说：「拇指关节再弯 0.04 rad」——21 个关节各给一个 [-1,1] 的小数。
_pre_physics_step把「再弯一点」叠到上一步目标上，得到本步绝对目标角；顺便记下物体上一帧位姿（后面算速度用）。
physics × 12仿真器默默算 12 次：手指推物体、物体反推手指、摩擦、重力……
_apply_action读回最新关节角，用 PD 公式算力矩，命令电机去追目标角。
_get_observations打包「最近 3 帧」传感器读数成 186 维，交给 PPO 下一拍决策。
_get_rewards物体绕目标轴转得快 → 正分；滑走了、力矩太大 → 扣分。
_get_dones物体高度跑出 4 cm 窗口 → 本局结束；或 20 秒到了 → 超时结束。
Q：policy 是 20 Hz，物理是 240 Hz，为什么不让策略也 240 Hz？
A：真机电机接口和通信带宽通常也是几十 Hz；更高频策略对 sim-to-real 帮助有限，却成倍吃显存和算力。decimation=12 是工程上常用的折中：物理够细、控制够省。

三、__init__：buffer 与启动自检

__init__ 只做两件事：验配置对不对（fail fast），预分配所有 GPU 张量（训练时避免每步 malloc）。仿真一步里反复读写的就是这些 buffer。可以把每个 buffer 想成游戏里的「常驻 UI 血条 / 小地图缓存」——开局分配好，整局反复用。

3.1 Layer 1 启动自检

    raise RuntimeError(...)

白话 walk-through · 启动自检
n_joints != cfg.action_spaceUSD 里加载的手有 21 个关节吗？cfg 说 action 也是 21 维——对不上说明 URDF 换过但 cfg 没改。
actuated_joint_names 逐个检查配置里写的关节名字，在 URDF 里真的存在吗？拼写差一个字母，训练一万步才发现就晚了。

raise RuntimeError故意「开局就崩」：宁可 0 步训练失败，也不要 silently 用错维度训到收敛。

这些检查在 super().__init__之后跑，因为那时 self.hand 已从 USD 加载完毕。URDF 关节名和 cfg 列表不一致时，训练跑一万步才发现就太晚了。

3.2 核心 buffer 逐个认识：「这个变量就像……」

下面不只列 shape，还用生活类比帮你建立肌肉记忆。所有张量都在 GPU（device=self.device）上，shape 第一维永远是 num_envs。

__init__ 预分配张量（完整版）
属性shape用途白话类比

proprio_hist_buf(N, 30, 62)最近 30 帧本体历史给 TConv 学生的「30 秒短视频」，用来猜摩擦/质量（06 章）
priv_info_buf(N, 8)特权信息：物块偏移、摩擦、质量、质心教师的「上帝面板」——学生部署时看不到
at_reset_buf(N,)标记刚 reset 的环境像「刚读档」旗子：下一步要把 80 帧历史全填成当前帧，避免冷启动全零

p_gain / d_gain(N, 21)PD 增益；reset 时可域随机电机「硬度」旋钮：P 大 = 追目标更猛，D 大 = 抑制抖动
scale_ids(N, 1)每个 env 分到哪个物体尺寸桶像 8 种粗细的笔芯；env 0–9 可能用细笔，env 10–19 用粗笔
saved_grasping_states(总行, 28)抓取缓存矩阵「成功握笔姿势相册」，每行 28 个数（18 章）
rot_axis(N, 3)期望旋转轴（单位向量）奖励问：物体绕这根轴转得多快？默认 (0,0,1) 竖轴
Q：为什么 obs 历史要 80 帧，policy 却只取 3 帧？
A：80 是为了给 proprio_hist_buf（30 帧）留够滑动空间；PPO 教师网络输入固定 186 维（62×3），是论文/部署端约定好的形状。多存的帧不会浪费——TConv 学生会读更长历史。

3.3 抓取缓存加载

xhand_wave_env.py · __init__ · grasp_cache 
scale_ids = ...  # 把 num_envs 均分给 scale_range[2] 个物体尺度

白话 walk-through · 抓取缓存加载
scale_ids = linspace(0,7,...)8 种物体直径（0.4–0.6 m 之间 8 档），均匀分给 num_envs 个并行环境。
np.load(path)从硬盘读「相册」；例如 50000 行 × 28 列（详见18 章）。
bucket_grasp = 总行数 / 8每个尺寸桶约 6250 种起手式；reset 时在这 6250 行里随机抽。
bucket_env = num_envs / 8例如 num_envs=80 → 每个尺寸分 10 个 env；它们共享同一个 6250 行的抽样池。
num_envs % 8 != 0 → exit()分桶必须整除，否则有的尺寸多一个 env、有的少一个，破坏对称性。

缓存每行是 [21 关节角 | 3 物体位置 | 4 物体四元数]，共 28 维。训练前须用 gen_grasp.py 生成（18 章）。

3.4 启动时域随机化（一次性）

摩擦、质心、质量在环境创建时对每个并行 env 采样一次，写入 priv_info_buf 对应槽位：

  • priv_info_buf[:, 3] ← 摩擦缩放系数（例如 0.8–1.2 之间随机）
  • priv_info_buf[:, 4] ← 物体质量（例如 0.05–0.15 kg）
  • priv_info_buf[:, 5:8] ← 质心偏移（mm 级随机）
域随机化像「开局给每个平行宇宙设不同物理法则」：env #3 的笔更滑、更重、质心偏一点；env #7 的笔更涩。教师策略带着 priv_info 看这些参数，学会「在多种手感下都能转」。

指尖弹性体摩擦通过 _compute_elastomer_shape_ids() 遍历 USD 碰撞 shape 索引，避免硬编码（Xhand URDF 每个 dip_link 有 4 个 collision shape）。

五、_pre_physics_step + _apply_action

5.1 动作 → 目标位

xhand_wave_env.py · _pre_physics_step 
actions = saturate(actions, -clip_actions, clip_actions)   # ±1
self.actions = actions.clone()
targets = self.prev_targets + self.cfg.action_scale * self.actions  # scale=1/24
self.cur_targets[:, actuated_dof_indices] = saturate(
    targets, hand_dof_lower_limits, hand_dof_upper_limits)
self.object_pos_prev[:] = self.object_pos      # 差分用
self.object_rot_prev[:] = self.object_rot
白话 walk-through · 增量动作
saturate(actions, ±1)神经网络输出可能爆掉；裁剪到 [-1,1]，像游戏手柄死区外的限幅。
prev_targets + action_scale * actions增量控制：action=+1 表示「在上一目标基础上再弯 1/24 rad」（约 2.4°）。
saturate(targets, 关节上下限)手指不能弯到物理不可能的角度——撞到 URDF 限位就卡住。
object_pos_prev[:] = object_pos在物理推进之前记下物体旧位置；奖励里用「新位置 − 旧位置」算速度。

可选外力扰动（force_scale > 0）：以概率 0.25 给物体施加随机力，带指数衰减——逼策略在「被推一下」时仍能稳住旋转。

5.2 PD 力矩写入仿真

xhand_wave_env.py · _apply_action 
self._refresh_lab()   # 从仿真读回关节角、速度、力矩、物体位姿
if self.cfg.torque_control:
    self.torques = p_gain * (cur_targets - hand_dof_pos) - d_gain * hand_dof_vel
    self.hand.set_joint_effort_target(torques[:, actuated_dof_indices], ...)
else:
    self.hand.set_joint_position_target(cur_targets[:, actuated_dof_indices], ...)
self.prev_targets[:, actuated_dof_indices] = cur_targets[:, actuated_dof_indices]
白话 walk-through · PD 控制
_refresh_lab()问仿真：「现在关节角多少？物体在哪？」抄到 self 的 buffer 里。
p_gain * (目标 - 当前角)P 项：离目标越远，力矩越大——像弹簧把你拉向目标角。
- d_gain * 关节速度D 项：转太快就刹车——防止手指抖成帕金森。
set_joint_effort_target把算好的力矩（Nm）写给 PhysX 电机。
prev_targets = cur_targets本步目标变「下一步的上一目标」——增量动作的锚点。

cfg 默认 torque_control=True：动作经 PD 变成力矩，更接近真机电机接口。每步末尾把 cur_targets 拷进 prev_targets，下一步增量才正确。

六、_reset_idx：开局采样

当某 env「掉落」或「超时」，父类会调用 _reset_idx(env_ids)。核心流程：

① super()._reset_idx

清 episode 计数、事件管理器默认重置

② PD 随机化

randomize_pd_gains 时重采样 p_gain/d_gain

③ 抓取缓存采样

每个 scale 桶内 randint(0, bucket_grasp) 抽一行姿态

④ 写物体

位置/四元数来自缓存 + env_origins；算本局高度上下界

⑤ 写手部

关节角 = 缓存前 21 维；prev/cur_targets 同步

⑥ 清 buffer

proprio_hist_buf=0，at_reset_buf=1（下一步观测会填满历史）

xhand_wave_env.py · _reset_idx · 缓存采样 
sampled_pose_idx = torch.randint(0, self.bucket_grasp, size=(self.bucket_env,))
for i in range(self.cfg.scale_range[2]):   # 8 个物体尺度
    saved_grasping_states_picked[i*bucket_env:(i+1)*bucket_env] = \
        saved_grasping_states[i*bucket_grasp:(i+1)*bucket_grasp][sampled_pose_idx]
sampled_pose = saved_grasping_states_picked[env_ids].clone()
dof_pos = sampled_pose[:, :self.num_hand_dofs]   # 前 21 维

sampled_pose[env_ids]只 reset 那些「刚 Game Over」的 env，别的 env 继续转笔。
dof_pos = 前 21 维把相册里的手指弯曲角度写回仿真——瞬间回到「已抓住」姿势。

高度终止窗口随物体初始高度自适应：

reset_height_lower[env_ids] = z_init - (reset_height_upper - reset_height_lower) / 2
reset_height_upper[env_ids] = z_init + (reset_height_upper - reset_height_lower) / 2

默认窗口宽 4 cm（cfg 0.59906 ~ 0.63906 相对掌心坐标系）。物体 z 超出即 height_reset=True。

高度窗口像「毽子高度安全带」：开局根据物体初始 z（比如 0.62 m）上下各放宽 2 cm。物体滑低到 0.60 m 或弹飞到 0.64 m 就判失败——逼策略在掌心附近稳稳转，而不是甩飞或捏碎。

reset_random_quat 当前 cfg 为 False（2026-06-02 临时关闭全 SO(3) 随机朝向，避免重力课程死锁）。开启时会绕手掌中心随机旋转整手+物体，并重算 rot_axis。

八、extras 与 TensorBoard

_get_rewards 把六项原始量、三轴角速度分量、重力分量写入 self.extras，wrapper 会打到 TensorBoard。调参时看 rotate_reward 是否上升、height_reset_* 是否接近 0。

Q：训练时 reward 曲线平了，先看 extras 里哪几条？
A：① rotate_reward 是否接近 0（可能根本没转起来）；② height_reset_upper/lower 是否很高（一直掉笔）；③ gravity_z 是否还在 −0.05（重力课程没加码说明还没学会稳握）。详见17 章调试表。

十、常见问题（FAQ）

Q：环境类和 cfg 类是什么关系？
A：cfg 是「菜单」——维度、频率、奖励系数全写在那里；环境类是「厨师」——按菜单做菜。改 action_space 只改 cfg 不够，环境 __init__ 自检会拦住你。
Q：super().__init__ 里到底发生了什么？
A：父类会：启动 Isaac Sim → 调你的 _setup_scene → 创建并行 env → 第一次 _reset_idx 所有 env。所以子类 __init__ 后半才能安全访问 self.hand。
Q：我只改了 URDF，训练启动就报 startup-check，怎么办？
A：对照报错里的 joint_names 列表，更新 xhand_wave_env_cfg.py 的 actuated_joint_names。关节数变了还要改 action_space 和网络输入维。
Q：num_envs=10 时，每个 buffer 第一维是 10 吗？
A：对。例如 prev_targets.shape == (10, 21) 表示 10 个并行宇宙各有一份关节目标；GPU 一次 kernel 就算完 10 行，这是 IsaacLab 比「for 循环 10 次单 env」快几个数量级的原因。
