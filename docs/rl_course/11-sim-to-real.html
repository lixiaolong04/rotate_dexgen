CHAPTER 11 · 收官深度章

Sim-to-Real 实战

仿真里练成的策略，怎么真的搬到一只会发热、有延迟、传感器带噪声的真手上转起来？这一章把"过桥"的每块木板拆开看。

一、现实落差（reality gap）到底是什么

你在驾校模拟器里练得出神入化，第一次开真车却手忙脚乱——方向盘更重、刹车更软、还有模拟器里没有的风噪和颠簸。仿真与真实之间这道"哪儿哪儿都差一点"的鸿沟，就是 reality gap。 sim-to-real 的全部努力，都是为了让"模拟器里的高手"一上真车也不翻。

这道鸿沟有四个主要来源，记住它们，后面每个技术都在堵其中一两个口子：

落差来源仿真里真机上
动力学质量/摩擦/质心是设定值未知、随物体而变、还会磨损
感知状态精确可读编码器有误差、触觉有噪声和漂移
延迟近似零延迟、定步长通信/计算/电机响应都要时间
驱动理想 PD、力矩立即生效电机有电流上限、有死区、会发热降额

二、三大流派：怎么过桥

学界堵 reality gap 有三条主路线。理解它们的取舍，才懂本项目为什么这么选。

流派思路代价 / 风险
系统辨识
(System ID)		把仿真精确校准到匹配这一台真机费力、换个物体就失效、永远有残差
域随机化
(Domain Randomization)		把仿真故意搞乱成千百种，逼出"放之四海皆准"的策略，零样本上真机太宽则学不动/保守；需要配合"认出当前世界"
域自适应
(Domain Adaptation / RMA)		训练时见多识广，部署时从历史在线推断当前是哪种世界需两阶段、要设计可推断的隐变量
本项目 = 域随机化 + 域自适应。 用域随机化（第 09 章）制造千万种世界 + RMA（第 06 章）让学生从历史认出"我现在身处哪种世界"。完全不做精细系统辨识——这正是它能换不同圆柱、零样本上真机的底气。
现实落差 & 域随机化覆盖
蓝色是仿真训练见过的参数分布，橙色竖线是这台真机的真实参数。拖"随机化宽度"：太窄会漏掉真机（zero-shot 失败），够宽才能罩住它。再拖"真机参数"模拟换了个更重/更滑的物体。

三、本项目的桥：三件套总览

把零散技术拼成一张图。真机部署时，只有学生通路在工作（无特权信息）：

① 域随机化（训练期）：质量、质心、PD 增益、随机外力、关节噪声、重力课程 → 制造世界的多样性，这些量同时是教师的特权信息。
② RMA 蒸馏（训练期）：TConv 从 30 帧历史估计隐变量 ẑ ≈ 教师的 z → 学会"认出当前世界"。
③ 观测/动作对齐（部署期）：保证真机喂给网络的每个数字，和仿真训练时含义、量纲、顺序完全一致 → 网络才不会"看错题"。

第 ①②已在第 09、06 章详讲，本章聚焦最容易被忽视、却最致命的第 ③ 件——以及延迟、触觉、部署运行时这些"真机才有的事"。

四、观测对齐：让真机和仿真"看到同一道题"

网络是个挑剔的考生：它只认训练时那套"题面格式"。哪怕真机测得再准，只要你把触觉力的单位、或者关节的排列顺序换了，对网络来说就是一道全新的、它没复习过的题——立刻翻车。所以部署的头等大事，是把观测一字一句对齐到训练时的样子。

仿真与真机用同一套单帧 64 维布局（部署变体 SharpaWave 为 22 DOF，观测 192 = 64×3 帧）：

$$64 \;=\; \underbrace{22}_{\text{归一化关节角}} + \underbrace{22}_{\text{控制目标}} + \underbrace{5}_{\text{指尖触觉}} + \underbrace{15}_{\text{接触点}}.$$

关节角在两边都用同一个 unscale 公式归一化到 $[-1,1]$，保证量纲一致：

$$\hat q \;=\; \frac{2q - (q_{\max}+q_{\min})}{q_{\max}-q_{\min}}.$$
sharpa_wave_deploy_env.py · compute_observations（与训练同构） 
cur_obs_buf = unscale(self.hand_dof_pos, lower, upper).unsqueeze(1)   # 关节角，同一归一化
cur_obs_buf = torch.cat([cur_obs_buf, cur_tar_buf], dim=-1)          # 拼控制目标
cur_obs_buf = torch.cat([cur_obs_buf, sensed_contacts, contact_pos], dim=-1)  # 触觉 + 接触点
self.obs_buf_lag_history = torch.cat([prev_obs_buf, cur_obs_buf], dim=1)
obs_buf = self.obs_buf_lag_history[:, -3:].reshape(num_envs, -1)     # 最近 3 帧 → 192
sim ↔ real 观测对齐
单帧观测分四块。点击任意一块，看它在仿真里的来源 vs 真机上的来源——对齐的关键就是"同一含义、同一量纲、同一位置"。
点一块观测看看它两边怎么对齐。
归一化统计量也要对齐！ 部署时 restore_test 不仅加载网络权重，还加载训练得到的 running_mean_std（观测归一化）和 sa_mean_std（历史归一化）。它们在部署时冻结（第 08 章）。少加载任何一个，输入分布就会偏移、策略行为漂移。

五、关节重映射：同一只手，两套编号

IsaacLab 和 SharpaWave 固件对 22 个关节的编号顺序不一样——就像同一支球队，仿真按身高排号、真机按位置排号。发指令前必须"翻译"一下号码，否则你想弯食指，真机却去弯了拇指。

代码用两张固定的置换索引来回翻译：发指令时 IsaacLab→SharpaWave，读状态时 SharpaWave→IsaacLab。它们互为逆置换。

utils/misc.py · 关节序重映射 
_ISAACLAB2SHARPA_IDX = torch.tensor([4,9,14,19,21,0,5,10,15,1,6,11,16,3,8,13,18,2,7,12,17,20])
_SHARPA2ISAACLAB_IDX = torch.tensor([5,9,17,13,0,6,10,18,14,1,7,11,19,15,2,8,12,20,16,3,21,4])

def dof_isaaclab2sharpa(dof_pos):  # 发给真机前：策略坐标 → 固件坐标
    return dof_pos.index_select(-1, _ISAACLAB2SHARPA_IDX)
def dof_sharpa2isaaclab(dof_pos):  # 读回状态后：固件坐标 → 策略坐标
    return dof_pos.index_select(-1, _SHARPA2ISAACLAB_IDX)
部署时的用法 
# 下发：策略算出的目标 → 翻译成固件顺序 → set
command = dof_isaaclab2sharpa(self.cur_targets.squeeze()).cpu().numpy()
self.hand.set_joint_position(command)
# 读取：固件返回角度 → 翻译回策略顺序
self.hand_dof_pos = dof_sharpa2isaaclab(torch.tensor(self.hand.get_states().angles))
关节重映射可视化（22 DOF 置换）
左列 IsaacLab 策略序，右列 SharpaWave 固件序，连线是 dof_isaaclab2sharpa 的对应。悬停任意关节高亮它去了哪儿。这就是"翻译号码"。

六、延迟与控制频率

真机的每一步都要花时间。本项目用固定控制频率 20 Hz，即每步目标节拍 $\Delta t_{\text{target}} = 1/20 = 0.05\text{s}$，并在循环里"睡"到节拍对齐，保证时序稳定：

$$\text{若 } \Delta t_{\text{loop}} < \Delta t_{\text{target}}：\quad \text{sleep}\big(\Delta t_{\text{target}} - \Delta t_{\text{loop}}\big).$$
sharpa_wave_deploy_env.py · step（节拍对齐） 
loop_dt = time.perf_counter() - self._last_step_wall
if loop_dt < self.target_dt:
    time.sleep(self.target_dt - loop_dt)     # 补足到 1/control_freq
self._last_step_wall = time.perf_counter()
符号表 · 延迟相关
量仿真真机
控制频率由 decimation 决定control_freq=20 Hz
感知延迟contact_latency 显式建模通信/计算固有延迟
触觉帧率—板载 30 fps / 主机 180 fps
为什么训练时就要建模延迟与噪声？ 因为延迟、触觉噪声、关节读数噪声都是 reality gap 的一部分。训练时在仿真里故意加上它们（第 09 章的 joint_noise、contact_latency、contact_sensor_noise），策略才会对真机的"不完美"免疫。这就是把"真机的脏"提前喂给策略。

七、触觉的 sim-to-real

触觉是这个项目的特色，也是 reality gap 的重灾区。两边要对齐成同一个"5 维指尖力"：

仿真真机
力从哪来接触传感器净力范数触觉模组的 F6 前 3 分量取范数
加工平滑 + 延迟 + 噪声 (+可二值化)force_scale 缩放 + 阈值置零 (+可二值化)
标定无需上电先 calibrate 归零基线
sharpa_wave_deploy_env.py · get_tactile_info（真机侧加工） 
force[ch] = torch.norm(torch.tensor(f6)[:3])   # F6 前三分量的范数 = 法向接触力
force *= self.cfg.force_scale                  # 1/1.5，把真机力缩放到训练量纲
force[force < self.cfg.contact_threshold] = 0  # 低于 0.2 视为无接触，抑噪
if self.cfg.binary_contact:
    force = torch.where(force > thresh, 1.0, 0.0)

触觉帧率可切换：--enable_on_board 用板载 30fps、省主机算力；默认主机模式 180fps、信息更密。两种都把信号对齐成训练时那套 5 维力 + 接触点占位。

八、部署运行时：上手的每一步

部署脚本只用学生（ProprioAdapt），推理循环极简——归一化观测与历史 → 取动作均值 → 下发：

scripts/deploy.py · 主循环（无特权信息） 
agent.restore_test(resume_path)     # 加载 model + running_mean_std + sa_mean_std
agent.set_eval()
obs_dict = agent.env.reset()
while True:
    input_dict = {
        'obs':          agent.running_mean_std(obs_dict['obs']),
        'proprio_hist': agent.sa_mean_std(obs_dict['proprio_hist'].detach()),
    }
    mu = agent.model.act_inference(input_dict)   # 取均值，不采样（第 03 章）
    obs_dict, _, _, _ = agent.env.step(mu)

先抓稳：warm-up 抓取轨迹

策略只会"转"，不会"从零抓起"。所以部署前先回放一段预录抓取轨迹，边合拢边看触觉力，一旦指尖感到接触就停，把这个抓握姿态作为策略的起手式：

sharpa_wave_deploy_env.py · _reset_idx（warm-up） 
traj = np.load('cache/deploy_init_traj.npy')
while torch.max(tactile_force) < 1 and j + 3 < len(traj):
    j += 1; self.hand.set_joint_position(traj[j]); time.sleep(0.03)
    tactile_force, _ = self.get_tactile_info()      # 抓到（力>1）就停
self.prev_targets = dof_sharpa2isaaclab(traj[j+2])  # 以此为策略起点

键盘状态机：人始终能接管

真机会伤人伤物，所以默认不自动跑，必须人按键启动，且随时能冻结或回零位。这是安全底线。
部署状态机（键盘控制）
点按钮模拟按键：e 启动策略 / w 冻结当前姿态 / q 回零位。高亮当前状态。真机上 Ctrl+C 会安全停手并断连。

九、Sim-to-Real 排错清单

  • 观测对齐：每块观测的含义、量纲、顺序与训练完全一致？关节用了同一个 unscale？
  • 归一化统计：running_mean_std 与 sa_mean_std 都加载了且处于 eval？
  • 关节重映射：下发用 isaaclab→sharpa、读取用 sharpa→isaaclab，没搞反？
  • 触觉：上电标定归零？force_scale 把真机力对齐到了训练量纲？阈值合理？
  • 动作：用均值（act_inference）而非采样？增量步长 action_scale 与训练一致？限位收了 0.9 裕度？
  • 时序：控制频率与训练近似？延迟/噪声在训练时已建模？
  • 安全：warm-up 抓稳了再跑？键盘能冻结/回零？电流系数限了力？
本章小结。 sim-to-real 的本质是堵动力学/感知/延迟/驱动四道落差。本项目走"域随机化 + RMA"路线零样本上真机，而真正落地的细节在于把观测/动作/触觉/时序逐字对齐训练时的样子，再加关节重映射、warm-up 抓取与键盘安全状态机。至此，从 MDP 到真机旋转的整条链路就全部打通了。
