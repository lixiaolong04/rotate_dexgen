RunningMeanStd 在线归一化

不存历史数据，也能边走边算出均值和方差。一个让训练稳得多的小模块，背后是优雅的并行合并公式。

一、为什么要归一化

我们的观测里，关节角也许在 ±1 之间，触觉力可能是几十牛。如果直接喂给网络，"大数值"的输入会主导梯度，"小数值"的输入几乎被忽略——就像一个班里有人用米、有人用毫米报身高，老师没法公平比较。
归一化把每一维都拉到"均值 0、标准差 1"的统一尺度，让网络对每一维一视同仁。这是深度强化学习里最便宜、最有效的稳定性技巧之一。

标准归一化公式人人都会：

$$\hat x \;=\; \frac{x - \mu}{\sqrt{\sigma^2 + \varepsilon}}.$$

难点不在这个公式，而在：训练时数据像水流一样一批批涌来，上万环境每步都产生新数据，我们不可能把它们全存下来再算 $\mu,\sigma$。 必须"边来边更新"。

二、朴素在线更新的陷阱

均值好办（累加再除），但方差若用"平方和 − 均值平方"的教科书公式在线累加，会因为两个大数相减产生灾难性抵消（catastrophic cancellation），浮点误差爆炸。我们需要数值稳定的算法——这就是 Welford / Chan 并行合并公式。

三、并行合并公式（代码核心）

设已有统计量 $(\mu, \sigma^2, n)$，现在来了一批新数据，其统计量为 $(\mu_b, \sigma_b^2, n_b)$。我们要把两者合并。先定义两组均值之差与总数：

$$\delta = \mu_b - \mu, \qquad n_{\text{tot}} = n + n_b.$$

① 新均值（加权平均）

$$\mu' \;=\; \mu + \delta\,\frac{n_b}{n_{\text{tot}}} \;=\; \frac{n\,\mu + n_b\,\mu_b}{n_{\text{tot}}}.$$

就是按样本数加权的平均，第一种写法是为了数值稳定（在旧均值基础上修正一点点）。

② 新方差（通过 M₂ 合并）

关键技巧是不直接合并方差，而是合并平方偏差和 $M_2 = \sigma^2 \cdot n$（sum of squared deviations）：

$$M_2' \;=\; \underbrace{\sigma^2 n}_{m_a} \;+\; \underbrace{\sigma_b^2 n_b}_{m_b} \;+\; \delta^2\,\frac{n\,n_b}{n_{\text{tot}}}, \qquad \sigma'^2 \;=\; \frac{M_2'}{n_{\text{tot}}}.$$
符号表 · 并行合并
符号含义（代码对应）
$\mu,\sigma^2,n$已累计的均值/方差/计数。代码 running_mean, running_var, count。
$\mu_b,\sigma_b^2,n_b$本批数据的均值/方差/样本数。代码 batch_mean, batch_var, batch_count。
$\delta$两组均值之差，代码 delta。
$m_a, m_b$两组各自的平方偏差和 $\sigma^2 n$ 与 $\sigma_b^2 n_b$。
$\delta^2\frac{n\,n_b}{n_{\text{tot}}}$修正项：因两组中心不同而额外产生的偏差，是公式的精髓。

③ 修正项从哪来？（给数学专业的推导）

平方偏差和的定义是 $M_2 = \sum_i (x_i - \mu)^2$。把两组数据合在一起、相对新均值 $\mu'$ 求平方偏差和。对第一组的每个点：

$$\sum_{i\in A}(x_i-\mu')^2 = \sum_{i\in A}\big((x_i-\mu)+(\mu-\mu')\big)^2 = \underbrace{\sum_{i\in A}(x_i-\mu)^2}_{m_a} + n(\mu-\mu')^2$$

（交叉项 $2(\mu-\mu')\sum_{i\in A}(x_i-\mu)=0$，因为 $\sum_{i\in A}(x_i-\mu)=0$）。对两组分别这样做，代入 $\mu-\mu' = -\delta\frac{n_b}{n_{\text{tot}}}$ 与 $\mu_b-\mu' = \delta\frac{n}{n_{\text{tot}}}$，合并整理即得：

$$M_2' = m_a + m_b + n\Big(\delta\tfrac{n_b}{n_{\text{tot}}}\Big)^2 + n_b\Big(\delta\tfrac{n}{n_{\text{tot}}}\Big)^2 = m_a + m_b + \delta^2\frac{n\,n_b}{n_{\text{tot}}}.$$

最后一步把 $\frac{n n_b^2 + n_b n^2}{n_{\text{tot}}^2} = \frac{n n_b (n_b+n)}{n_{\text{tot}}^2} = \frac{n n_b}{n_{\text{tot}}}$ 化简即可。这个修正项保证了无论分多少批来，结果都和"一次性算全部"完全一致，且数值稳定。

running_mean_std.py · _update_mean_var_count_from_moments 
delta = batch_mean - mean
tot_count = count + batch_count
new_mean = mean + delta * batch_count / tot_count
m_a = var * count
m_b = batch_var * batch_count
M2 = m_a + m_b + delta**2 * count * batch_count / tot_count
new_var = M2 / tot_count
new_count = tot_count
在线均值/方差的收敛
数据从一个真实分布（虚线）一批批流入。看"在线估计"的均值与标准差如何随样本累积，稳稳收敛到真值。

四、前向：归一化与裁剪

训练模式下，每次前向都先用当前 batch 更新统计量，再做归一化，并把结果裁剪到 ±5（挡住极端离群值）：

running_mean_std.py · forward 
if self.training:
    mean = input.mean(self.axis); var = input.var(self.axis)
    self.running_mean, self.running_var, self.count = \
        self._update_mean_var_count_from_moments(..., mean, var, input.size()[0])
# 归一化
y = (input - current_mean) / torch.sqrt(current_var + self.epsilon)
y = torch.clamp(y, min=-5.0, max=5.0)
训练 / 评估两种模式。 训练时持续更新统计量；评估或部署时冻结统计量（.eval()），只用已学好的 $\mu,\sigma$ 做归一化。否则部署时少量数据会污染统计、导致行为漂移。第 05 章 PPO 里对 running_mean_std 的 train/eval 切换正是为此。

五、价值也归一化：还能反归一化

本项目不仅归一化观测，还归一化价值（value）（value_mean_std，形状 (1,)）。因为不同任务回报量级差异巨大，归一化让 Critic 更好训。但有时需要把网络输出的"归一化价值"还原回真实尺度——于是有反归一化（unnorm=True）路径：

$$x \;=\; \sqrt{\sigma^2+\varepsilon}\;\cdot\;\clip(\hat x,\,-5,\,5)\; +\; \mu.$$

它正好是归一化的逆运算（先解除缩放再加回均值）。代码里 PPO 用它把价值预测在"归一化空间"与"真实空间"之间来回切换。$\varepsilon$（默认 1e-5）始终在根号里，防止除零/开零。

本章小结。 RunningMeanStd 用 Welford/Chan 并行公式在线、稳定地维护均值与方差，核心是合并平方偏差和 $M_2$ 时的修正项 $\delta^2\frac{n n_b}{n_{\text{tot}}}$。前向归一化并裁到 ±5；训练时更新、评估时冻结；价值用同款模块并支持反归一化。下一章是最后一个配角，也是 sim-to-real 的灵魂：域随机化。
