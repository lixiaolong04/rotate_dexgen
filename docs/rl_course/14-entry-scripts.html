本章术语速查

AppLauncher
Isaac Sim 的「开机按钮」。必须在 import pxr、物理引擎之前调用，否则进程会崩或挂起。
argparse
Python 标准库，解析你在命令行写的 --num_envs 10 等参数，放进 args_cli 对象。
Hydra
配置框架：根据 --task 自动加载对应的 env cfg 和 agent yaml，并支持 env.xxx=yyy 覆盖。
装饰器 @hydra_task_config
写在 def main(...) 上面的「补丁」：调用 main() 前，Hydra 先把两个配置准备好，作为参数传进来。
Wrapper（包装器）
GymStyleEnvWrapper 在真环境外包一层，统一动作裁剪、观测格式，让 PPO 不用关心 IsaacLab 细节。
checkpoint
已训练权重的存档（.pth）。restore_train 用于续训；restore_test 用于 play 推理。
headless
无图形界面跑仿真，省显存；服务器和笔记本训练通常必加 --headless。
VecEnv（向量化环境）
多个环境并行，一次 step 处理整批动作张量 (num_envs, 21)，而不是 for 循环。
读 train.py 像看飞机起飞检查单：先点火（AppLauncher）→ 装燃油配置（Hydra）→ 乘客登机（gym.make）→ 机长就位（PPO）→ 起飞（agent.train()）。gen_grasp.py 和 play.py 是同一型号的飞机，但目的地不同。
你可能会问：为什么 train.py 文件中间有一条注释 """Rest everything follows."""？
这不是随便写的——这条线以上只能做启动仿真所需的事；线以下才能 import IsaacLab / gym / 项目模块。顺序错了，Isaac Sim 5.x 经常直接报错退出。

一、三个入口，三种使命

把 rl_isaaclab/scripts/ 想成工厂的三条流水线：gen_grasp.py 是「备料车间」——只让手保持当前姿态、让物理引擎把合法抓握姿态存进缓存；train.py 是「主生产线」——PPO 或 ProprioAdapt 在这里跑几百万步；play.py 是「质检窗口」——加载 checkpoint，关随机化，开 GUI 看策略转得稳不稳。三条线共用同一套「启动仿真 → Hydra 读配置 → gym.make → Wrapper」的前半段，后半段分道扬镳。

二、所有脚本的第一幕：AppLauncher

三个文件的开头完全一致：在 import 任何 IsaacLab 模块之前，先解析 CLI、启动 Omniverse 应用。这是 Isaac Sim 的硬性要求——pxr、物理引擎、USD stage 都依赖已启动的 simulation_app。

train.py · 第 7–33 行（gen_grasp / play 同构） 
import argparse
import sys

from isaaclab.app import AppLauncher

parser = argparse.ArgumentParser(description="Train an RL agent.")
parser.add_argument("--num_envs", type=int, default=16384, ...)
parser.add_argument("--task", type=str, default=None, ...)
# ... 更多 train/play 专用参数 ...
AppLauncher.add_app_launcher_args(parser)
args_cli, hydra_args = parser.parse_known_args()

sys.argv = [sys.argv[0]] + hydra_args   # 把剩余参数留给 Hydra

app_launcher = AppLauncher(args_cli)
simulation_app = app_launcher.app

代码白话解释

"""Rest everything follows.""" 这行注释之后才开始 import gymnasium、torch、项目模块——顺序不能乱。

3.2 @hydra_task_config 装饰器

train.py · main 入口 
@hydra_task_config(args_cli.task, "agent_cfg_entry_point")
def main(env_cfg: DirectRLEnvCfg, agent_cfg: dict):
    ...

装饰器根据 --task 对应的 gym spec，读取两个 entry point：

  • env_cfg_entry_point → 实例化 XhandWaveEnvCfg（Python dataclass）
  • agent_cfg_entry_point → 加载 ppo_cfg.yaml（dict）

调用 main() 时，Hydra 已把 YAML 与 dataclass 合并好，作为两个参数传入。

Hydra 像餐厅套餐默认值：--task 决定点哪套（Xhand 训练 / 抓取）；YAML 和 py cfg 是套餐内容；你在命令行加的 --num_envs 10 是「少辣」「加饭」——最后厨房（main）收到的是已经改好的单子。
@hydra_task_config 两行
代码白话解释
@hydra_task_config(args_cli.task, "agent_cfg_entry_point")第一个参数：任务名（来自命令行 --task）；第二个：去 gym 注册表里找 agent 配置的键名。
def main(env_cfg, agent_cfg)函数体里拿到的已是「默认配置对象」，还没被 train.py 里 CLI 覆盖。

你可能会问：为什么 --num_envs 要同时改 env_cfg.scene.num_envs 和 agent_cfg["algorithm"]["num_actors"]？
前者告诉 Isaac Sim「开几个并行仿真窗口」；后者告诉 PPO「rollout 时有几条并行轨迹」。两个数不一致会导致张量 shape 对不上、直接报错或 silent bug。
CLI 覆盖块 · 典型模式 x if 命令行给了 else 用默认
模式白话解释

对 agent 和 env 各写一遍 seed/device算法随机性（初始化网络）和环境随机性（物体位置）要同一个种子才完全可复现。
min(num_envs * 8, 32768)小显存机器：10 个 env → minibatch 80；大数据中心：最多 cap 在 32768。

3.4 ProprioAdapt 专用重力修正

train.py · 蒸馏阶段重力 
if agent_cfg["algo"] == "ProprioAdapt":
    env_cfg.gravity_curriculum = False
    env_cfg.sim.gravity = (0.0, 0.0, -9.81)  # 蒸馏必须在真实重力下!

Stage 1 PPO 训练时重力从 -0.05 起步做课程；关课程后若仍用近失重，student 在 Stage 2 学不到真机条件。因此蒸馏分支强制真实重力。

Stage 1 像在室内游泳池学换气（近失重，容易抓稳）；Stage 2 要下海（真重力）。如果蒸馏时还在游泳池，学生以为「物体总是很轻」，上真机就摔笔。

3.6 gym.make 与 Wrapper

train.py · 环境创建 
env = gym.make(args_cli.task, cfg=env_cfg, render_mode=None)
env = GymStyleEnvWrapper(env, clip_actions=env_cfg.clip_actions)

gym.make 根据注册表实例化 XhandWaveInhandRotateEnv，传入已覆盖的 env_cfg。GymStyleEnvWrapper 做三件事：把 IsaacLab env 适配成 PPO 需要的 VecEnv 接口；按 clip_actions（默认 1.0）裁剪动作；构造时自动 reset() 一次。

gym.make + Wrapper · 两行
代码白话解释
gym.make(args_cli.task, cfg=env_cfg, ...)任务名必须是已注册 ID；cfg= 把改好的配置灌进环境构造函数。
GymStyleEnvWrapper(env, clip_actions=...)包装后 env.step 返回 PPO 期望的 dict obs；动作超出 [-1,1] 会被裁掉。

3.7 eval(algo) 与 checkpoint

train.py · 智能体与训练 
agent = eval(agent_cfg["algo"])(env, output_dir=log_dir, full_config=config)

spec = gym.spec(args_cli.task)
env_cfg_file = spec.kwargs.get("env_cfg_entry_point", None).split(":")[0].replace(".", "/") + ".py"
agent_cfg_file = spec.kwargs.get("agent_cfg_entry_point", None).replace(".", "/").replace(":", "/").replace("/yaml", ".yaml")
shutil.copy(env_cfg_file, os.path.join(log_dir, f"env_cfg_{agent_cfg['algo']}.py"))
shutil.copy(agent_cfg_file, os.path.join(log_dir, f"agent_cfg_{agent_cfg['algo']}.yaml"))

if args_cli.resume or agent_cfg["algo"] in ["ProprioAdapt"]:
    resume_path = agent_cfg["load_path"]
    agent.restore_train(resume_path)

agent.train()
env.close()

eval("PPO") 等价于 PPO(...)。训练前会把当时用的 env/agent 配置快照复制进 log 目录，便于复现。restore_train 加载 model + running_mean_std（训练态）；ProprioAdapt 或 --resume 时必走此分支。主循环在 agent.train() 里，直到 max_agent_steps（详见第 05 章与第 20 章）。

四、gen_grasp.py：零动作无限循环

抓取缓存生成的逻辑极简：让手「维持当前关节目标、不施加策略动作」，物理引擎在重力与接触下自然收敛到稳定抓握；环境内部检测到稳定后把关节角+物体位姿写入 .npy。脚本本身不训练、不加载网络，只负责驱动仿真步进。可以把它想成自动拍照机：手摆好姿势后，环境负责按快门把状态存盘，脚本只负责「一直让仿真往前走」。
你可能会问：为什么叫「零动作」？手不是还在动吗？
「零动作」指策略输出的增量为 0（zero_actions 全 0 张量），不是「手完全静止」。手仍受 PD 控制维持当前目标角，物体在重力下微动；环境认为稳定后就记录一帧抓取状态。
gen_grasp.py · 完整 main（精简注释） 
@hydra_task_config(args_cli.task, "agent_cfg_entry_point")
def main(env_cfg: DirectRLEnvCfg, agent_cfg: dict):
    shutil.rmtree('outputs/', ignore_errors=True)
    env_cfg.scene.num_envs = args_cli.num_envs if args_cli.num_envs is not None else env_cfg.scene.num_envs
    env_cfg.seed = args_cli.seed if args_cli.seed is not None else agent_cfg['seed']
    env_cfg.sim.device = args_cli.device if args_cli.device is not None else env_cfg.sim.device
    agent_cfg["algorithm"]['minibatch_size'] = min([args_cli.num_envs * 8, 32768])

    env = gym.make(args_cli.task, cfg=env_cfg, render_mode=None)
    env = GymStyleEnvWrapper(env, clip_actions=env_cfg.clip_actions)

    env.reset()
    while True:
        actions = env.zero_actions()   # shape (num_envs, 21)，全零增量
        _ = env.step(actions)
gen_grasp.py main · 逐段白话
代码白话解释
@hydra_task_config + 精简 CLI 覆盖同样用 Hydra 加载 grasp 任务配置；只改 num_envs/seed/device/minibatch（后一项其实用不上）。
gym.make + Wrapper创建抓取专用环境类（episode 更短、逻辑偏向写缓存）。
env.reset()显式 reset 一次（Wrapper 构造时也会 reset，这里是双保险）。
while True:无限循环，直到你 Ctrl+C 或环境内部认为缓存够多。
zero_actions() + step每步送全 0 动作；环境推进物理并可能往 cache/*.npy 追加数据。

对比 train.py，注意缺失的部分：

  • 无 ConfigWrapper、无 PPO import
  • 无 --load_path、--cache、--algorithm 等 train 专用 CLI（文件里未定义）
  • 无 checkpoint、无 agent.train()
  • shutil.rmtree('outputs/', ignore_errors=True) — 忽略 Hydra 临时目录删除失败

zero_actions() 在 Wrapper 里返回与动作空间同 shape 的全零张量，表示「本步不改变关节目标增量」：

sharpa_wave_env_wrapper.py 
def zero_actions(self) -> torch.Tensor:
    return torch.zeros((self.num_envs, self.num_actions), device=self.device)

典型命令（见第 10 章）：

python rl_isaaclab/scripts/gen_grasp.py \
  --task Isaac-Inhand-Rotate-Grasp-Xhand-Wave-v0 --headless

任务 ID 带 Grasp，对应 xhand_wave_grasp_env 与更短的 episode（12s），专门服务缓存生成。

五、play.py：测试模式可视化

play.py 与 train.py 共享大量 CLI 覆盖逻辑，但目标是加载策略、关随机化、无限推理。

训练是「考场里随机出题」（域随机化）；play 是「固定同一道题反复演给你看」。所以 play 默认关掉摩擦、质量、PD 等随机项，并固定物体尺寸，这样你看到的转笔效果才稳定、可对比不同 checkpoint。
你可能会问：play 为什么不调用 agent.train()？
因为 play 的目的不是更新网络权重，而是只看已训练策略的表现。agent.test() 内部循环：观测 → 网络推理动作 → env.step，不反向传播、不写 checkpoint（除非你自己改代码）。

5.2 ConfigWrapper(test=True) 与 restore_test

十四点五、checkpoint 加载再讲一遍

ppo.py · restore_train vs restore_test（完整） 
def restore_train(self, fn):
    checkpoint = torch.load(fn)
    self.model.load_state_dict(checkpoint['model'])
    self.running_mean_std.load_state_dict(checkpoint['running_mean_std'])

def restore_test(self, fn):
    checkpoint = torch.load(fn)
    self.model.load_state_dict(checkpoint['model'])

checkpoint 里有什么 · 为什么 play 可以少加载
键训练要不要推理要不要白话
model要要神经网络权重，策略「大脑」。
running_mean_std要（训练态）输入归一化要；value 部分推理不用观测归一化的滑动平均；推理时要用同一套缩放。
优化器状态（若有）续训可能要不要restore_test 根本不碰优化器。
你可能会问：--resume 和 --load_path 有什么区别？
--load_path 只指定文件路径；--resume 是开关，告诉 train.py 在 PPO 阶段也要 restore_train。ProprioAdapt 即使用户不写 --resume，只要 algo 是 ProprioAdapt 也会强制加载 stage1。
.pth 像游戏存档：restore_train 是「读档继续练级」；restore_test 是「只读人物外观和装备进观战模式」，不需要经验条和背包里训练专用的东西。

小结：train.py 第 101–105 行决定是否读档；第 108 行才开始真正「练级」。

可以。在 VS Code/Cursor 里对 PPO、hydra_task_config 按 F12；train.py 本身只有 118 行，适合分屏：左边 HTML walk-table，右边源文件对照行号。行号以仓库当前版本为准，若你本地文件有增删，以 wc -l 为准。
