CHAPTER 05 · Stage 1 主算法

PPO 核心算法

近端策略优化：用一把"裁剪剪刀"约束每次更新的步子，做到小步快跑、稳而不翻。

代码详解。 PPO 在本仓库的实现见 Part B 第 20 章（play_steps / train_epoch 逐行）；全链路复盘见 第 22 章。

一、出发点：策略梯度

我们要最大化目标 $J(\theta)$（第 01 章）。最朴素的办法是策略梯度定理给出的方向：

$$\nabla_\theta J(\theta) \;=\; \EE_{\tau\sim\pi_\theta}\!\left[\sum_t \nabla_\theta \log\pi_\theta(a_t\mid s_t)\,\hat A_t\right].$$
这个式子其实很好懂：把每个动作的"出现概率的对数"往上推或往下压，推多少由优势 Â 决定。优势为正（这步是好棋）→ 提高它的概率；优势为负（臭棋）→ 降低它的概率。第 04 章辛苦算的 Â，就是用在这里。

朴素策略梯度的致命伤

问题是：这个梯度只在"当前策略附近"才准。如果一步迈太大，策略剧变，之前采的数据全部失效，训练直接崩盘。我们需要一个机制：既朝好方向走，又不许一步迈太远。

二、概率比 r(θ)

PPO 用重要性采样比（概率比）衡量"新策略相对旧策略，把这个动作的概率改了多少"：

$$r_t(\theta) \;=\; \frac{\pi_\theta(a_t\mid s_t)}{\pi_{\theta_{\text{old}}}(a_t\mid s_t)} \;=\; \exp\!\big(\log\pi_\theta - \log\pi_{\theta_{\text{old}}}\big).$$
  • $r_t = 1$：新旧策略对这个动作看法一致。
  • $r_t > 1$：新策略更爱这个动作。
  • $r_t < 1$：新策略更嫌弃它。
ppo.py · train_epoch 
ratio = torch.exp(old_action_log_probs - action_log_probs)
surr1 = advantage * ratio
surr2 = advantage * torch.clamp(ratio, 1.0 - self.e_clip, 1.0 + self.e_clip)
a_loss = torch.max(-surr1, -surr2)
代码命名小陷阱。 这里 old_action_log_probs 和 action_log_probs 存的其实是 neglogp（负对数概率）。所以 exp(old_neglogp − new_neglogp) = exp(logp_new − logp_old) = r(θ)，符号正好对上，结果就是上面公式里的概率比。别被变量名骗了。

三、裁剪代理目标（PPO 的灵魂）

PPO 最大化下面这个裁剪代理目标，对每个样本取两项的较小值：

$$L^{\text{CLIP}}(\theta) \;=\; \EE_t\Big[\, \min\big(\,r_t\,\hat A_t,\;\; \clip(r_t,\,1-\epsilon,\,1+\epsilon)\,\hat A_t\,\big)\Big].$$
符号表 · 裁剪目标
符号含义
$r_t$概率比。
$\hat A_t$标准化后的 GAE 优势（第 04 章）。
$\epsilon$裁剪半径（代码 e_clip，本项目 = 0.2），即"每步最多改动 ±20%"。
$\clip(r,1-\epsilon,1+\epsilon)$把概率比强行夹在 $[0.8,1.2]$。
$\min(\cdot,\cdot)$取两项较小，得到原目标的悲观下界。

为什么"取小"就能防止迈太大？

分两种情况看（这是理解 PPO 最关键的一段）：

情况行为
优势 Â > 0（好动作，想提高概率）当 $r$ 已经涨到 $1+\epsilon$ 以上，裁剪项把它封顶，目标不再增大 → 没有动力把概率推得更高。好动作也不许一次性吹太猛。
优势 Â < 0（坏动作，想降低概率）当 $r$ 已经跌到 $1-\epsilon$ 以下，裁剪项托底 → 没有动力把概率压得更低。坏动作也不许一次性打死。
裁剪就像给方向盘加了限位器：你可以打方向，但一次最多打 20%。方向对（Â>0）也别猛打死，方向错（Â<0）也别猛回死。这样每次更新都待在"数据还可信"的安全区里，所以 PPO 能反复用同一批数据训好几轮（mini_epochs=5）而不崩。
裁剪函数曲线（PPO 的标志性图）
横轴是概率比 r，纵轴是每样本目标值。切换优势正负、拖动 ε，看裁剪如何"封顶/托底"。红色虚框是裁剪安全区。

四、价值损失（也带裁剪）

Critic 要去拟合第 04 章算出的回报 $\hat R_t$。本项目同样对价值做了裁剪，防止 Critic 一步乱跳：

$$L^{V} = \max\!\Big[(V_\theta - \hat R)^2,\;\big(V_{\text{clip}} - \hat R\big)^2\Big],\quad V_{\text{clip}} = V_{\text{old}} + \clip\big(V_\theta - V_{\text{old}},\,-\epsilon,\,\epsilon\big).$$
ppo.py · train_epoch 
value_pred_clipped = value_preds + (values - value_preds).clamp(-self.e_clip, self.e_clip)
value_losses = (values - returns) ** 2
value_losses_clipped = (value_pred_clipped - returns) ** 2
c_loss = torch.max(value_losses, value_losses_clipped)   # 取大 = 更保守的回归

这里取 max（而非策略目标的 min），因为价值是"损失要最小化"，取大同样起到"惩罚过激更新"的保守作用。

五、边界损失：把动作均值拉回合理范围

动作会被裁到 ±1，但若网络一味把 $\mu$ 推到很大（比如 5），会卡在边界、梯度消失。边界损失温柔地惩罚 $|\mu|>1.1$ 的部分：

$$L^{b} = \sum_i \Big[\big(\max(0,\;\mu_i-1.1)\big)^2 + \big(\max(0,\;-\mu_i-1.1)\big)^2\Big].$$

在 $[-1.1,1.1]$ 内为 0（不干预），越界后二次增长。系数 bounds_loss_coef=0.0001，很轻。

六、总损失：四项合一

$$L \;=\; \underbrace{L^{\text{actor}}}_{-L^{\text{CLIP}}} \;+\; \tfrac12\,c_v\,L^{V} \;-\; c_e\,\mathcal{H} \;+\; c_b\,L^{b}.$$
ppo.py · train_epoch 
loss = a_loss + 0.5 * c_loss * self.critic_coef \
       - entropy * self.entropy_coef + b_loss * self.bounds_loss_coef
符号表 · 总损失各系数（本项目取值）
符号代码值作用
$c_v$critic_coef4价值损失权重（这里很大，强调 Critic 准确性）。
$c_e$entropy_coef0熵奖励权重（本项目关闭，见第 03 章）。
$c_b$bounds_loss_coef1e-4边界损失权重。
$\mathcal H$entropy—策略熵；前面是减号，所以最小化总损失 = 鼓励高熵。

之后照常反向传播 + 梯度裁剪（grad_norm=1.0）+ Adam 更新。

七、KL 自适应学习率

除了裁剪，本项目还用第二道保险：监控新旧策略的 KL 散度，自动调学习率。两个对角高斯之间的 KL 有解析式，代码逐维计算：

$$D_{\mathrm{KL}}\big(\pi_{\text{old}} \,\|\, \pi_{\text{new}}\big) = \sum_i \Big[\underbrace{\log\tfrac{\sigma_{1,i}}{\sigma_{0,i}}}_{c_1} + \underbrace{\frac{\sigma_{0,i}^2 + (\mu_{1,i}-\mu_{0,i})^2}{2\,\sigma_{1,i}^2}}_{c_2} \underbrace{-\tfrac12}_{c_3}\Big].$$
符号表 · 高斯 KL
符号含义
$\mu_0,\sigma_0$旧策略（采样时）的均值与标准差，代码 p0_mu, p0_sigma。
$\mu_1,\sigma_1$新策略（更新后）的均值与标准差，代码 p1_mu, p1_sigma。
$c_1$标准差比的对数项：两个分布"胖瘦"差异。
$c_2$均值漂移 + 方差比项：分布"中心"挪了多少。
$c_3=-\tfrac12$常数项，来自高斯 KL 的解析推导。
ppo.py · policy_kl 
c1 = torch.log(p1_sigma/p0_sigma + 1e-5)
c2 = (p0_sigma ** 2 + (p1_mu - p0_mu) ** 2) / (2.0 * (p1_sigma ** 2 + 1e-5))
c3 = -1.0 / 2.0
kl = (c1 + c2 + c3).sum(dim=-1).mean()

算出 KL 后，AdaptiveScheduler 按一个简单规则调学习率（目标 KL kl_threshold=0.02）：

$$\text{lr} \leftarrow \begin{cases} \text{lr}/1.5, & D_{\mathrm{KL}} > 2\,\text{KL}^\star \quad(\text{改太猛，踩刹车})\\[4pt] \text{lr}\times 1.5, & D_{\mathrm{KL}} < 0.5\,\text{KL}^\star \quad(\text{改太怂，给油门})\\[4pt] \text{lr}, & \text{其它（刚刚好）} \end{cases}$$

并夹在 $[10^{-6}, 10^{-2}]$。这让学习率随训练动态自调，比固定学习率稳健得多。

KL → 学习率 自适应调度器（模拟器）
设定每个 epoch 测到的 KL，点"前进一步"应用规则，观察学习率怎么被 ×1.5 / ÷1.5 地拉回。蓝带是目标区间 [0.5·KL*, 2·KL*]。

八、训练主循环

① 采样 play_steps

用当前策略在上万个并行环境里跑 horizon_length=8 步，收集 (obs, action, reward, value, neglogp...)。

② 算优势 computer_return

反向递推 GAE（第 04 章），得到 advantages 与 returns，并标准化。

③ 多轮 minibatch 更新 train_epoch

把这批数据切成 minibatch，重复 mini_epochs=5 遍：算 ratio、裁剪目标、价值损失、反传、Adam。

④ 调学习率

每个 mini-epoch 末用平均 KL 更新学习率。

⑤ 记录 / 存档

写 TensorBoard，按 reward 存 best / last 检查点，回到 ①。

本章小结。 PPO = 策略梯度 + "裁剪剪刀"（限制每步幅度）+ 价值裁剪 + 边界损失 + KL 自适应学习率。这五件套让它能在上万并行环境里稳定、高效地把教师策略训出来。但教师用了仿真特权信息，真机没有——下一章 RMA 来解决这个鸿沟。
