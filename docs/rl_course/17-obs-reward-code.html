📖 本章术语速查

policy obs（186 维）
喂给 PPO 教师网络的观测向量。= 最近 3 个控制步的「单帧 62 维」拼在一起。
单帧 62 维
某一时刻的传感器快照：21 关节 + 21 目标 + 5 触觉 + 15 接触点（后 15 维当前全 0）。
unscale
把关节角从物理弧度映射到 [-1, 1]。限位中点 → 0，弯到上限 → +1，弯到下限 → −1。
priv_info（8 维）
仿真里才知道的「上帝信息」：物体滑移、摩擦、质量、质心。教师可见，部署学生不可见。
proprio_hist（30×62）
最近 30 帧本体感历史。ProprioAdapt 学生用 TConv 从这里估计被藏起来的物理参数。
滑动窗口 lag history
80 帧 FIFO 队列：每步把最新 62 维挤进队尾，最老一帧挤出去。
rotate_reward
主奖励：物体绕 rot_axis 的角速度，裁剪到 ±0.5 后乘 scale 2.5。
height_reset
物体 z 高度超出本局 4 cm 窗口 → episode 终止（真 Game Over）。

一、三个函数的输出契约

_get_observations 返回三份数据，像一次体检出三张报告单：
  • policy（186 维）→ 给 PPO 教师：「你现在手啥样、上一拍目标啥样、触觉多大」
  • priv_info（8 维）→ 给教师的「透视挂」：物体滑没滑、摩擦多大（学生看不到）
  • proprio_hist（30×62）→ 给蒸馏学生的「30 帧短视频」
_get_rewards 返回每个 env 一个标量分数；_get_dones 返回 (terminated, time_out) 二元组——前者是掉笔，后者是时间到。

二、单帧 62 维与 186 维索引表

$$\text{单帧 62} = \underbrace{21}_{\hat q} + \underbrace{21}_{\text{targets}} + \underbrace{5}_{\text{contact}} + \underbrace{15}_{\text{contact\_pos}}, \qquad \text{policy obs 186} = \text{单帧} \times 3\ \text{（最近三帧拼接）}.$$

滑动窗口 obs_buf_lag_history 深 80 帧，但策略只取最后 3 帧 reshape 成 186 维。帧顺序是从旧到新：索引 0–61 是 $t-2$，62–123 是 $t-1$，124–185 是 $t$（当前拍）。

把 186 维想成三连拍照片：左边一张两拍前的手，中间一张上一拍，右边一张刚刚拍的。神经网络同时看三帧，才能感觉「手指是在加速弯还是已经弯到位」——单帧看不出动态。

unscale 把关节角从物理限位映射到 $[-1,1]$：

$$\hat q = \frac{2q - q_{\max} - q_{\min}}{q_{\max} - q_{\min}}.$$
举例：某关节限位 $[0, 1.5]$ rad，当前 $q=0.75$（正中间）→ $\hat q = 0$。弯到 $1.5$ → $\hat q=+1$。网络输入永远在 [-1,1]，不同关节物理范围差很多也不影响训练尺度。

五、_get_rewards 与 compute_rewards

先算六个原始标量（每个 env 一个 float），再经 @torch.jit.script 的 compute_rewards 加权求和。

5.1 六项原始量

_get_rewards 六项
#变量名计算默认 scale典型量级正负
①rotate_rewardsaturate((ω·n̂), -0.5, 0.5)+2.50.1–0.5主奖励
②object_linvel_penalty$\|x_t-x_{t-1}\|_1 / \Delta t$-0.30.01–0.5 m/s惩罚
③pos_diff_penalty$\sum_i (q_i - q_i^{\text{def}})^2$-0.40.5–3.0惩罚
④torque_penalty$\sum_i \tau_i^2$-0.11–50惩罚
⑤work_penalty$(\sum_i \tau_i \dot q_i)^2$-0.50.1–10惩罚
⑥object_pos_diff$1 / (\|x_t - x^{\text{def}}\| + 0.001)$+0.00310–1000小奖励
口算一例： 物体绕 z 轴以 0.4 rad/s 旋转 → rotate_reward=0.4 → 贡献 0.4×2.5=+1.0。同时物体滑了 0.02 m/s → linvel_penalty≈0.02 → 贡献 −0.006。主项仍是旋转，其它是「别滑、别拧麻花、别费电」的护栏。
xhand_wave_env.py · 旋转奖励核心 
object_angvel = axis_angle_from_quat(
    quat_mul(self.object_rot, quat_conjugate(self.object_rot_prev))
) / self.step_dt
rotate_reward = saturate(
    (object_angvel * self.rot_axis).sum(-1),
    angvel_clip_min, angvel_clip_max)   # 默认 ±0.5
白话 walk-through · 旋转奖励
quat_mul(r, conj(r_prev))两帧姿态差 → 这段时间转了一个小的旋转。
axis_angle_from_quat / step_dt转成角速度向量 ω (rad/s)。
ω · rot_axis只奖励绕期望轴（默认竖轴 z）的分量——横着晃不算分。
saturate(±0.5)单步角速度贡献封顶，防止物理爆炸时 reward 飞天。
xhand_wave_env.py · compute_rewards（JIT） 
@torch.jit.script
def compute_rewards(rotate_reward, rotate_reward_scale,
                    object_linvel_penalty, object_linvel_penalty_scale,
                    pos_diff_penalty, pos_diff_penalty_scale,
                    torque_penalty, torque_penalty_scale,
                    work_penalty, work_penalty_scale,
                    object_pos_diff, object_pos_reward_scale):
    reward  = rotate_reward         * rotate_reward_scale
    reward += object_linvel_penalty * object_linvel_penalty_scale
    reward += pos_diff_penalty      * pos_diff_penalty_scale
    reward += torque_penalty        * torque_penalty_scale
    reward += work_penalty          * work_penalty_scale
    reward += object_pos_diff       * object_pos_reward_scale
    return reward
白话 walk-through · JIT 加权
@torch.jit.script编译成 TorchScript，仿真热路径少 Python 开销——每秒几千次调用。
六项线性加权没有复杂 if-else；调参就是改 cfg 里六个 scale 系数。
penalty scale 为负原始量是正数（力矩平方等），乘以负 scale → 从总 reward 里扣。

Q：time_out 和 height_reset 在 PPO 里有区别吗？

十、常见问题（FAQ）

Q：186 维里有没有物体位置？
A：policy 观测没有物体位姿——只有手本体感+触觉。物体信息只在 priv_info 前 3 维（偏移量）给教师。学生部署时完全看不到，必须从手指感觉推断。
Q：为什么关节角既 unscale 又留原始值？
A：索引 0–20 是网络习惯吃的 [-1,1] 归一化值；索引 21–41 的 targets 槽在正常运行存的是控制目标（弧度），reset 时 temporarily 存原始角。这是与 SharpaWave 原版和部署端的历史约定。
Q：六项 reward 可以先关掉五项只训旋转吗？
A：可以把 cfg 里五个 penalty scale 设为 0，但不建议长期如此——力矩和滑移惩罚是防止 sim 里学到「暴力拧笔」的关键护栏，关掉后策略常出现过拟合仿真噪声。
