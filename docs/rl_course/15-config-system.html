配置系统：从 gym.register 到 PPO

读完本章，你能回答：Isaac-Inhand-Rotate-Xhand-Wave-v0 注册时传了哪三个 kwargs？action_space=21 和 actuated_joint_names 如何对应？ppo_cfg.yaml 里每个键在 PPO 代码哪一行被读？CLI 和 YAML 谁覆盖谁？

前置阅读。 入口脚本如何把配置用起来见第 14 章。环境一步里这些字段如何消费见第 16 章（下一章）。奖励项含义见第 02 章；PPO 公式见第 05 章。

零、读代码之前

配置听起来抽象，其实就是可调旋钮的清单：仿真多快、奖励多重、网络多大……本章教你这些旋钮写在哪些文件、谁覆盖谁、拧错会怎样。

本章术语速查

gym.register
向 Gymnasium「登记」一个任务：名字、环境类在哪、默认配置从哪读。类似给 App 在应用商店上架。
entry_point
字符串路径，告诉 Python 去哪个模块找环境类或配置文件，格式常是 包.模块:类名。
kwargs
「keyword arguments」关键字参数；在 gym.register(..., kwargs={...}) 里是随任务附带的额外信息（配置入口等）。
@configclass
IsaacLab 装饰器，把类变成带默认值的配置 dataclass；字段可嵌套 SimulationCfg 等子配置。
YAML
人类可读的层级配置文件，扩展名 .yaml；本项目 PPO 超参在 ppo_cfg.yaml。
Hydra 覆盖
命令行形如 env.scene.num_envs=10 的写法，运行时改 cfg 字段，不必改磁盘上的 py 文件。
ConfigWrapper
小盒子：.train 装算法 dict，.task 装环境 dataclass，交给 PPO 和部署代码。
域随机化（domain randomization）
训练时随机改摩擦、质量、PD 等，让策略更鲁棒；play 时通常关掉以便可视化稳定。
配置像游戏设置菜单：xhand_wave_env_cfg.py 是「画面/物理/难度」；ppo_cfg.yaml 是「AI 学习率/训练回合数」；命令行是「开始游戏前临时改的难度」。菜单默认值在文件里，你每次启动仍可覆盖。
你可能会问：我该改 py 还是改 yaml 还是只改命令行？
只改并行数 → 命令行 --num_envs 就够。改奖励/仿真 → 改 xhand_wave_env_cfg.py 并重新训练。改 PPO 学习率、网络宽度 → 改 ppo_cfg.yaml。改网络宽度后旧 .pth 往往不能续训（shape 对不上）。

一、配置从哪来、到哪去

可以把配置想成三层「默认值」叠在一起：最底层是 Python 文件 xhand_wave_env_cfg.py 和 YAML ppo_cfg.yaml 里写死的默认；中间层是 Hydra 在 @hydra_task_config 里按 gym 注册信息加载并实例化；最顶层是你在命令行写的 --num_envs 10 等覆盖。最终合并结果分别喂给 gym.make(cfg=env_cfg) 和 PPO(..., full_config=ConfigWrapper(...))。
配置优先级栈（可悬停）
越靠上的层优先级越高。CLI 覆盖 Hydra 运行时；Hydra 覆盖 yaml/py 默认值。
把鼠标移到某一层，这里会显示该层如何覆盖下层。

gym.register 像给任务办身份证：id 是姓名（命令行 --task 用的）；entry_point 是「人住在哪」（环境类文件）；kwargs 是「档案里还挂了哪两份说明书」（env cfg + agent yaml）。
tasks/inhand_rotate/__init__.py · Xhand 训练任务 
gym.register(
    id="Isaac-Inhand-Rotate-Xhand-Wave-v0",
    entry_point=f"rl_isaaclab.tasks.inhand_rotate.xhand_wave_env:XhandWaveInhandRotateEnv",
    disable_env_checker=True,
    kwargs={
        "env_cfg_entry_point": f"{__name__}.xhand_wave_env_cfg:XhandWaveEnvCfg",
        "agent_cfg_entry_point": f"{agents.__name__}:ppo_cfg.yaml",
    },
)
gym.register · 零基础逐项讲解（像填表一样）
参数名本项目的值白话解释 · 改了会怎样
idIsaac-Inhand-Rotate-Xhand-Wave-v0任务对外名字。改：命令行 --task 也要改；旧文档/脚本里的名字会对不上。
entry_point...xhand_wave_env:XhandWaveInhandRotateEnv「模块路径:类名」→ gym.make 时实例化这个环境类。改：指错类会 import 失败或跑到错误仿真逻辑。
disable_env_checkerTrue关掉 Gymnasium 对观测/动作空间的严格自检（大规模 vec env 常过不了）。改 False：可能启动时报 warning 或直接不让注册。
kwargs["env_cfg_entry_point"]...xhand_wave_env_cfg:XhandWaveEnvCfgHydra 用来实例化环境配置 dataclass 的地址。改：会加载另一套仿真参数（如 grasp cfg）。
kwargs["agent_cfg_entry_point"]...agents:ppo_cfg.yamlHydra 用来读取 PPO yaml 的路径。改：学习率、网络结构等全变；需与算法代码兼容。
你可能会问：为什么说「三个 kwargs」？表里不是五个参数吗？
口语里的「三个」常指：entry_point（环境类指针）+ env_cfg_entry_point + agent_cfg_entry_point。再加上 disable_env_checker 就是注册表上所有「额外选项」。本课程表格五列全列，避免数错。
你可能会问：f"{__name__}.xhand_wave_env_cfg:..." 里 __name__ 是什么？
当前模块名，这里是 rl_isaaclab.tasks.inhand_rotate。拼出来等于「从 inhand_rotate 包里的 xhand_wave_env_cfg 模块取 XhandWaveEnvCfg 类」，这样移动包时路径自动对。
gym.register 字段说明
字段值（Xhand 训练）作用
idIsaac-Inhand-Rotate-Xhand-Wave-v0--task 参数；gym.make 查表键
entry_pointxhand_wave_env:XhandWaveInhandRotateEnv环境类的 import 路径
disable_env_checkerTrue跳过 Gymnasium 对超大 vec env 的检查

用户说的「三个 kwargs」通常指注册表里除 id/entry_point 外、Hydra 真正消费的两个 entry point，加上 disable_env_checker=True 这一注册选项；有时也把 entry_point 本身算作「指向环境的第三指针」。本课程表格按上表五列完整列出，避免遗漏。

三、xhand_wave_env_cfg.py 分段导读

XhandWaveEnvCfg 继承 IsaacLab 的 DirectRLEnvCfg，用 @configclass 装饰。下面按功能块解读与训练直接相关的字段（文件约 338 行）。每个字段尽量回答两件事：它管什么、改错了会怎样。

你可能会问：为什么要在一个 py 文件里写几十行默认值，不全放 yaml？
环境 cfg 强依赖 IsaacLab 类型（SimulationCfg、ArticulationCfg…），IDE 能补全、嵌套结构清晰；PPO 超参是纯数值，放 yaml 更方便扫一眼改学习率。这是 IsaacLab 生态的常见分工。

3.1 维度与控制频率

xhand_wave_env_cfg.py · 环境与控制 
@configclass
class XhandWaveEnvCfg(DirectRLEnvCfg):
    episode_length_s = 20.0
    action_space = 21
    observation_space = 186  # (21 joint_pos + 21 targets + 5 contact + 15 contact_pos) * 3 frames
    prop_hist_len = 30
    priv_info_dim = 8
    decimation = 12
    clip_obs = 5.0
    clip_actions = 1.0
    action_scale = 1 / 24
    torque_control = True
3.1 字段逐条 · 改了会怎样
字段默认值白话 · 改了会怎样
episode_length_s20.0一局最长秒数。改大：每局更久，样本相关性强；改小：更频繁 reset，抓取缓存消耗快。
action_space21策略输出维度，必须等于 len(actuated_joint_names)。改而不改关节列表：测试失败 / 运行时 shape 错误。
observation_space186策略观测总维数，必须与 _get_observations 实际拼接一致。改错：PPO 网络输入维对不上。
prop_hist_len30给 TConv 网络的历史帧数（与上面 3 帧堆叠不同）。改：需同步改网络与部署 obs 构造。
priv_info_dim8特权信息维数（仿真里才有、真机没有的量）。改：须与 yaml priv_info_dim 一致。
decimation12每 12 个物理步才执行一次 RL 动作 → 20Hz 控制。改大：控制变慢；改小：更细但更耗算力。
clip_obs / clip_actions5.0 / 1.0观测/动作裁剪范围，防数值爆炸。改太小：信息被截断，策略变钝。
action_scale1/24网络输出 × 该系数才变成关节增量。改大：手抖、易掉物；改小：动作迟缓难转笔。
torque_controlTrueTrue=力矩模式；False=位置模式。改：与真机执行器模型不一致会 sim2real 变差。
维度公式（186 维观测）
块维数含义
joint_pos21当前关节角（策略序）
targets21上一步动作映射后的目标角
contact5五指指尖触觉标量
contact_pos15接触位置（cfg 中 enable_contact_pos=False 时可能为零填充）
× 3 frames×3历史堆叠（非 TConv 输入；TConv 另用 30 帧）
合计186(21+21+5+15)×3

decimation = 12：仿真步长 dt = 1/240 s，每 12 个物理步才执行一次 RL 动作，故控制频率为 240/12 = 20 Hz，与真机部署一致。

decimation 像游戏里的「每 N 帧才读一次手柄」：物理引擎仍 240 FPS 细算碰撞，但 AI 只 20 次/秒做决定，和真实 Xhand 控制频率对齐。

3.2 sim + scene · 改了会怎样
字段默认值白话 · 改了会怎样
sim.dt1/240物理仿真时间步。改：与 decimation 联动改变控制频率；一般勿乱改。
sim.gravity(0,0,-0.05)训练起步近失重，配合 gravity_curriculum。改成立即 -9.81：早期难抓、掉落多；蒸馏时 train.py 会强制改回。

replicate_physicsFalse物理是否跨 env 复制优化。改：一般保持默认，除非你做 IsaacLab 性能调优。

scene.num_envs 是 YAML/CLI 最常改的参数：默认 16384 面向数据中心 GPU；笔记本 12GB 显存用 --num_envs 10 覆盖。 env_spacing 防止并行实例碰撞体重叠。

3.3 robot 相关 · 改了会怎样
字段白话 · 改了会怎样

看 actuated_joint_names[0]，当前是 right_hand_thumb_mcp0_joint（拇指）。网络输出向量的下标与列表下标严格对应，部署真机时也必须同一顺序（见 deploy 章节）。

3.4 奖励系数

xhand_wave_env_cfg.py · rewards 
rot_axis = (0, 0, 1)

正奖励鼓励绕 Z 轴角速度（转笔）；负项惩罚线速度、位置漂移、力矩与做功。具体计算公式在 xhand_wave_env.py 的 _get_rewards（第 17 章展开）。

3.4 奖励系数 · 改了会怎样（调参直觉）
字段默认白话 · 改了会怎样
rot_axis(0,0,1)鼓励绕哪根轴转笔（Z 竖轴）。改：策略会绕别的轴蹭动。
angvel_clip_min/max-0.5 / 0.5角速度奖励裁剪，防异常尖峰。改宽：偶发大力矩可能拿高分。
rotate_reward_scale2.5转笔正奖励权重。改大：更激进旋转，易甩飞；改小：不愿转。
object_linvel_penalty_scale-0.3惩罚物体线速度（别乱扔）。绝对值改大：更稳但转速可能下降。
pos_diff_penalty_scale-0.4惩罚物体偏离掌心。改大：更要求物体待在手里。
torque_penalty_scale-0.1惩罚大力矩，省能、护硬件。改大：动作更「软」。
work_penalty_scale-0.5惩罚做功（力×位移）。改大：更少无效蹭动。
object_pos_reward_scale0.003小正项稳住物体位置。改大：可能牺牲转速换稳定。
奖励像绩效考核表：转得快加分，扔出去扣分，费电扣分。scale 是每项的「权重分」；改表之后要重新训练，旧策略是按旧表优化的。

3.5 grasp_cache_path 与随机化

xhand_wave_env_cfg.py · 缓存与域随机 
grasp_cache_path = 'cache/xhand_grasp_linspace'

scale_range = [0.4, 0.6, 8]
events.rand_params(scale_range)
randomize_pd_gains = True
randomize_friction = True
randomize_com = True
randomize_mass = True

grasp_cache_path 是前缀：环境按 scale_range 拼出如 cache/xhand_grasp_linspace_0.4-0.6-8.npy。训练前必须先跑 gen_grasp.py 生成对应文件（第 14 章）。scale_range 必须与 grasp cfg 一致，否则 reset 读不到缓存。

3.5 缓存 + 随机化 · 改了会怎样
字段默认白话 · 改了会怎样
grasp_cache_pathcache/xhand_grasp_linspace抓取 npy 文件名前缀。改而无对应文件：reset 报错或手张开摔物。
scale_range[0.4,0.6,8]物体尺寸随机：最小、最大、档位数。与 grasp 缓存后缀不一致：找不到 npy。
randomize_pd_gainsTrue每 reset 随机缩放 PD。改 False：仿真更「干净」，sim2real 鲁棒性可能下降。
randomize_frictionTrue随机摩擦。改 False：训练分布变窄，真机滑/涩可能不适应。
randomize_com / massTrue随机质心、质量。改 False：物体动力学更固定。
gravity_curriculumTrue掉落少则逐渐加大重力。改 False：一直用 sim.gravity 初值（近失重），真机落差大。
force_scale 等2 / 0.25 …随机推物体扰动。改大：更难抓，策略更鲁棒或学不会。
dof_limits_scale0.9关节限位缩到 URDF 的 90%。改：与真机可动范围对齐用；太大可能撞限位。
joint_noise_scale0.02关节读数噪声。改大：观测更脏，逼策略不依赖完美反馈。
你可能会问：我只改了 scale_range，还要做什么？
必须：① 用相同 scale_range 改 grasp env cfg；② 重新跑 gen_grasp.py 生成新后缀的 npy；③ 再训练。少一步就会在 reset 时 FileNotFound 或抓到错误尺寸物体。

3.5b EventCfg 与 scale 随机化

        self.randomize_scale = EventTermCfg(

EventCfg · 改了会怎样
部分白话 · 改了会怎样

六、Hydra 加载流程（串联）

整条链像快递分拣：--task 是收件人姓名 → gym 登记表查到两箱货（env cfg + agent yaml）→ Hydra 拆箱成对象 → train.py 根据 CLI 贴新标签 → ConfigWrapper 装箱 → PPO 签收。
  1. 用户：python train.py --task Isaac-Inhand-Rotate-Xhand-Wave-v0 --num_envs 10
  2. gym.spec(task).kwargs 取出两个 entry point 字符串
  3. Hydra 实例化 XhandWaveEnvCfg()，加载 ppo_cfg.yaml → main(env_cfg, agent_cfg)
  4. train.py 用 CLI 覆盖 env_cfg / agent_cfg 字段
  5. ConfigWrapper(agent_cfg, env_cfg) → PPO(env, full_config=config)
  6. PPO 从 full_config.train 读超参，从 env.action_space 读维度（必须与 cfg 一致）
$$\text{spec(kwargs)} \xrightarrow{\text{Hydra}} (env\_cfg, agent\_cfg) \xrightarrow{\text{CLI}} (env\_cfg', agent\_cfg') \xrightarrow{\text{ConfigWrapper}} \text{PPO/env}$$
你可能会问：CLI、Hydra、train.py 里的赋值，到底谁优先级最高？
对同一字段：train.py 里显式 CLI 覆盖（如 --num_envs）> Hydra 命令行（如 env.scene.num_envs=10）> yaml/py 文件默认值。日常改并行数用 --num_envs 最简单。

九、YAML 在 train_epoch 中的消费

除 __init__ 外，下列键在 PPO 训练循环里直接影响 loss（对应第 05 章公式）：

ppo.py · train_epoch 核心（节选） 
surr1 = advantage * ratio
surr2 = advantage * torch.clamp(ratio, 1.0 - self.e_clip, 1.0 + self.e_clip)
a_loss = torch.max(-surr1, -surr2)

value_pred_clipped = value_preds + (values - value_preds).clamp(-self.e_clip, self.e_clip)
c_loss = torch.max((values - returns)**2, (value_pred_clipped - returns)**2)

loss = a_loss + 0.5 * c_loss * self.critic_coef - entropy * self.entropy_coef + b_loss * self.bounds_loss_coef

if self.truncate_grads:
    torch.nn.utils.clip_grad_norm_(self.model.parameters(), self.grad_norm)

av_kls = torch.mean(torch.stack(ep_kls))
self.last_lr = self.scheduler.update(self.last_lr, av_kls.item())  # kl_threshold

play_steps 里 value_bootstrap 与 gamma 处理 timeout：

ppo.py · shaped_rewards 
shaped_rewards = 0.01 * rewards.clone()
if self.value_bootstrap and 'time_outs' in infos:
    shaped_rewards += self.gamma * res_dict['values'] * infos['time_outs'].unsqueeze(1).float()

你可能会问：kwargs 里还能塞别的键吗？
Gymnasium 允许，但本项目 Hydra 只认 env_cfg_entry_point 和 agent_cfg_entry_point。乱塞键不会被 train 用到，除非你自己改 hydra_task_config 逻辑——初学者不要试。

记住：--task 字符串 = __init__.py 里 gym.register(id=...) 的 id；拼错一字，Hydra 就找不到配置入口。
